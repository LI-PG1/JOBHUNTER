### 1.5 judge 混合判定（hard_check H1-H6 + 仲裁）

> 决策：P1-A 强制同城 / P2-B 学历不足降分 / P3-A 边界区交 LLM 仲裁（2026-08-14 用户确认）。

| # | 硬约束 | 规则 | 否决语义 |
|---|---|---|---|
| H1 | 地域 | 强制同城：岗位城市 ≠ 画像城市 → **硬否决**；岗位 city 缺失 → 不否决（-5 降分标注） | P1-A 硬否决 |
| H2 | 学历 | 画像学历 < 岗位要求 → **-10 降分**；岗位要求缺失 → 不扣分 | P2-B 降分 |
| H3 | 企业档 | 企业类型 ∉ 用户五档 → **硬否决** | 硬否决 |
| H4 | 时效 | 距今 > fresh_days（60/90/120 按模式）→ **硬否决** | 硬否决 |
| H5 | 来源 | `source_url` 非合法 http → **硬否决**（防编造，从 Gate3 前置） | 硬否决 |
| H6 | 技能匹配度 | `< gap`（50/55/60）→ 硬否决；`[gap, accept)`（70/75/80）→ **LLM 仲裁**；`≥ accept` → 收录 | 半否决 |

**合并仲裁（final_score）**：

```
final_score = clamp(match_score + edu_penalty(−10) + llm_adjust, 0, 100)
llm_adjust ∈ [-30, +20]   # 护栏截断：LLM 软分不得让硬分偏离超区间
收录判定：
  H1/H3/H4/H5 否决            → excluded（带 exclude_reason）
  match_score < gap           → excluded
  边界区 [gap, accept) 仲裁后 final_score ≥ accept → accepted；否则 gap
  其余                        → accepted（按 final_score 排序）
```

**否决输出**：所有否决带结构化 `exclude_reason`，供大脑 N7 差距分析聚合（"被拒最多原因 = 地域/学历/技能缺口"）。

### 1.6 LLM 软性维度与权重（Q2 · 2026-08-14 确认）

**维度取舍**（判定对象为真实搜索结果——有 JD 原文/公司锚点，属可交叉验证的"内容审核"）：

| 维度 | 判定内容 | 锚点强度 | 主观度 | 取舍 |
|---|---|---|---|---|
| jd_fit | JD 与画像的内容契合（技能线/业务方向/职责语义） | 强 | 中 | ✅ 核心维度 |
| quality | 岗位本身质量（信息完整度/招聘真实性/外包嫌疑） | 中 | 低-中 | ✅ 保留（降噪） |
| growth | 发展潜力（团队/业务前景） | 弱（信息稀缺易过时） | 高 | ⚠️ 降级为展示项，**不参与 llm_adjust** |

**LLM 输出**（每维度 `-1（差）~ +1（好）`）：
```json
{"items": [{"index": 0, "fit": 0.5, "quality": 0.2, "growth": 0.0,
            "fit_reason": "...", "confidence": "med"}]}
```

**合成公式**（growth 不计权）：
```
llm_adjust = clamp(round(30*fit + 15*quality), -30, +20)
```

| 维度 | 权重值 | 占比 | 语义 |
|---|---|---|---|
| jd_fit | ±30 | 67% | 主导——契合度决定主要微调 |
| quality | ±15 | 33% | 降噪——补足信息质量判断 |
| growth | 0 | 0% | 仅展示（清单标注"业务前景"），不计分 |

**护栏非对称（-30/+20）语义**：下调自由、上调受限——LLM 可大力打压可疑岗位（防错收），抬高分数受限（防乐观虚高）。防御性设计，宁缺毋滥。

**仲裁边界（硬语义优先，LLM 只管边界）**：
```
< gap（50/55/60）        → excluded     （LLM 无权捞回）
[gap, accept)             → LLM 仲裁档位  （final ≥ accept → accepted，否则 gap）
≥ accept（70/75/80）      → accepted     （LLM 分只影响 final_score 排序）
```

**运行时兜底**：judge 无 Key 方案已取消（D13），LLM 软分**运行时异常** → `llm_adjust=0`（纯 hard_score）+ 记 trace（故障保活，非无 Key 方案）。

**验证要点**（后续 mock 测试）：fit=+1/qual=+1 → adjust 截断 +20；fit=-1/qual=-1 → -30；fit=+1 但 match_score<gap → 仍 excluded；边界区 adjust 使 final≥accept → accepted；LLM 异常 → adjust=0。

**交叉验证**（Gate3 cross_check）：LLM 打分 vs 规则打分偏差分档——`>30` 否决该条目、`15~30` 标"待复核"、`≤15` 通过。

| 约束 | 规则 | 类型 |

### 2.3 内容生成确定性红线（✅ 2026-08-20 对齐 JL-Agent PRD §6.x，见《简历内容生成规范-resume_agent.md》）

| 约束 | 规则 | 类型 |
|---|---|---|
| 数量硬性约束 | 项目条数 = 目标页数 + 实习条数硬定（实习 0/1/2 → 一页 2/1/1、两页 3/2/1）；压缩/扩充不增减条数 | 生成 |
| criticality 裁剪 | 四级 low→medium→high→critical；critical 绝不裁剪；溢出压缩按序执行 | 生成/审核 |
| STAR 四段 | 项目 items 前 4 条语义固定 S/T/A/R；T 含量化目标、R ≥ T；S→T→R 断链 → blocker | 生成/审核 |
| 数字口径 | 每个量化数字须带口径 ∈ {评估集/受控压测/监控聚合/试点前后/团队统计}；无量纲/量级失配 → blocker | 生成/审核 |
| 数值精度 | 百分比取整或 1 位小数、延迟按量级取整、吞吐/人数取整；**禁极端值**（1000% 提升、0 成本） | 生成 |
| 时间约束 | 倒序（最晚在前）/ 无重叠 / 项目⊆实习（有实习时）；违反以「改项目时间（内容不变）」修复 | 审核 |
| 密度均衡 | 组内相对 ≥0.75（等效字）+ 单条绝对下限（实习 ≥45 / 项目 ≥35） | 审核 |
| 两页填充率 | 每页可用高（A4 减 18mm 四边）填充率 ≥85%；收敛阈值 ≥85% 填满 / 75~85% 可接受 / <75% 扩充 / >100% 压缩，≤3 轮（两页以第 2 页为准）；排版层 `_content_usage` 估算 + `_auto_density` 升档防空白 | 生成/验收 |
| 底部空白 | 页面底部连续空白 ≤ 内容可用高 25% | 验收 |
| 条目头单行 | 荣誉四条等分单行（装配层 `_abbr_honor` 缩写/截断）；教育/实习/项目条目头不折行（模板 `.item-title{white-space:nowrap}`，两页 11pt） | 生成（模板层） |
| 零截断 | 整条保留或整条删除，绝不截断句子；STAR 四要素不删；容量由排版吸收 | 生成 |
| 公司脱敏 | ai-created 不虚构真实公司/职级；需公司感语境用「某（行业）公司」 | 生成 |
