# 面试跟踪助手（本地应用）

> 把「投了哪、走到哪一步、下一步该干嘛」管清楚：置顶聚焦、自助维护、自动重排、节点提醒。
> 数据 100% 保存在本地 `data/投递数据.json`，无网络依赖、无账号、无数据采集。

## 3 分钟上手

1. **启动**：双击 `start.bat`（Windows）或运行 `bash start.sh`（macOS / Linux）。首次运行会自动生成 `config.json` 并自检环境。
2. **打开**：浏览器自动打开 `http://127.0.0.1:8902`（未自动打开时手动访问该地址）。
3. **使用**：
   - 点「＋ 新增投递」录入新岗位（必填：公司 / 岗位 / 工作类型，必填未填无法保存；其余均为选填），也可直接填流程环节；
   - 直接复制粘贴一坨杂乱投递信息到顶部「✨ 智能识别」常驻输入栏 → 点「识别补充」→ **核对确认表单后再保存**（确认界面「工作类型」四选项并列：秋招 / 有转正实习 / 日常实习 / 未知，识别不出时默认「未知」可修改）；
   - 首次使用智能识别需先点「⚙ API」配置大模型（只需选厂商、模型并粘贴 API Key，接口地址自动匹配）；**未配置或校验未通过的 API Key → 应用处于离线模式，智能识别栏自动置灰不可用**；
   - 每行「更新」推进流程环节（初筛 → 笔试 → 一面 → 二面 → 三面 → HR面 → 结果）；
   - 行内「置顶」聚焦重点，有面试的投递自动置顶按时间排序；**置顶/取消后自动滚动定位到该卡片**，直观看到它在重排后的位置；
   - 卡片「📝 备注」**点击展开为完整多行、再点收起**（有备注的岗位不必点进编辑即可看全）；**「展开 ▾」按键仅在备注确实被截断时自动出现**（模块化测量，完整展示的备注无按键）；待办事项与置顶栏内容**全量展示**（自动换行，不截断）；
   - 顶部 Tab 切换 全部 / 实习 / 秋招 / Offer（默认「全部」）；搜索框 + 状态/城市筛选（城市为单独城市，多城市岗位在各城市筛选下都出现）；
   - 「🔔 节点提醒」汇总未来 7 天面试、笔试截止与期限待办，≤24h 自动高亮，**点击提醒条目直接跳转到对应投递卡片**；**已出现在置顶栏的岗位自动从待办中去重（同一岗位的提醒只出现一次）**；右下角常驻「↑」回到顶部按钮。

停止：关闭启动器窗口（或终端 Ctrl+C）即可。数据实时保存，无需手动导出。

## 能力清单

| 能力 | 说明 |
|------|------|
| 置顶栏（双粒度） | 岗位级 + 公司级置顶，多置顶按先后排列、共存；跨分类常驻 |
| 自助新增 / 更新 | 表单录入与进度推进，重复岗位有合并提示，必填有校验；新增即可填流程环节 |
| 智能识别（AI） | 顶部常驻「智能识别」输入栏：粘贴杂乱投递信息 → 自动抽取 → 确认表单可改后再保存（未识别项单独提示）；识别结果先归一化为与「手动添加」完全一致的数据结构，再与手填走同一套排序/分流算法；**识别到面试信息 → 自动默认「简历/笔试已通过」（有面试=前置环节必已通过），并自动补一面「待进行」轮**；自动提取笔试截止、「期限待办」（如 8-15 前完成注册）与 Offer 有效期；**确认界面「工作类型」四选项并列（秋招 / 有转正实习 / 日常实习 / 未知），识别不出时默认「未知」可修改**；**无法归入结构化字段的信息（流程终止、实习项目、注册/加群/预约要求、邀请码、时间要求等）由算法判断写入备注** |
| API 配置 | 「⚙ API」= **API Key 管理控制台**：查看态（在线/离线状态徽标 + 当前配置卡[厂商/模型/接口/Key 掩码] + 🔄 测试连接 / ✏️ 重新配置 / 🗑 清除配置，打开自动测试连通性）+ 编辑态（选厂商 + 模型 + 粘贴 Key，接口地址自动匹配）；Key 只存本地 config.json（不回显明文）；内置 12 家厂商预设（DeepSeek / 智谱 GLM / OpenAI / 通义千问 / Moonshot Kimi / 腾讯混元 / 百度千帆 / 讯飞星火 / MiniMax / 零一万物 / 硅基流动 / Groq），仅提供可稳定遵循 JSON 抽取的达标模型（不含本地小模型与轻量/免费级） |
| 离线 / 在线模式 | 未配置或校验未通过的 API Key → 离线模式：智能识别栏置灰禁用（其余功能全部可用）；配置成功即自动转在线并解除置灰 |
| 自动重排 | Offer 待确认单独分组（进行中之后，**所有 Offer 一律归入「Offer 待确认」，无终态 Offer 分组**）→ 面试/笔试紧迫按时间升序 → 手动置顶 → 常规 → 终态挂/放弃；**终态（挂/放弃）岗位自动排除于置顶栏与待办提醒，也不按残留面试时间置顶**（环节自动归一化为「挂」，残留 interviewAt 自动清空） |
| 工作类型 | 四并列选项（秋招 / 有转正实习 / 日常实习 / 未知）：卡片标签 + 四并列 Tab（全部 / 实习 / 秋招 / Offer，**默认「全部」**，秋招 Tab=工作类型「秋招」，实习 Tab=非秋招含「未知」）；**工作类型独立筛选器（秋招 / 有转正实习 / 日常实习 / 未知），有转正实习在常规排序中优先**；筛选为空时提示在「更新」弹窗补充 |
| 置顶栏 | Offer 待确认（最优先）+ 面试/手动置顶双分区；**点击任意 chip 跳转到对应投递卡片并高亮**（✕ 按钮除外） |
| 筛选与搜索 | 关键词 + 状态 + 城市（**城市选项为单独城市**，多城市岗位「北京/上海」在 北京、上海 各自的筛选中都出现）+ **工作类型（秋招 / 有转正实习 / 日常实习 / 未知）**，叠加生效 |
| 面试提醒 | 未来 7 天节点栏（Offer 截止 14 天窗口）+ 有截止时间的节点（笔试/待办/Offer）恒标红 + ≤24h 行高亮红；**点击提醒条目跳转到对应投递卡片并高亮**；**置顶栏已展示的岗位在待办中自动去重**；「待办事项」标题右侧实时时钟（跟随系统时间，YYYY/MM/DD HH:mm，24 小时制） |
| 回到顶部 | 右下角常驻圆形「↑」图标按钮（滚动后显示，无文字，点击平滑回顶） |
| 数据持久化 | 本地 JSON 原子读写，刷新不丢失 |
| 一键运行 | start.bat / start.sh + `--selftest` 自检，零依赖（Node 18+）；**桌面启动器「面试跟踪助手.bat」**：服务未运行→自检并启动（保持窗口开启即服务运行中，浏览器自动打开）；服务已运行→直接打开浏览器 |

## 环境要求

- Node.js ≥ 18（检查：`node -v`；未安装：Windows 运行 `winget install OpenJS.NodeJS.LTS`）
- 无需 npm install，无任何第三方依赖
- 智能识别需自备大模型 API Key（如 DeepSeek：https://platform.deepseek.com；模型可选 **DeepSeek-V4-Flash**（快、便宜、日常够用）/ **DeepSeek-V4-Pro**（更强推理、更贵））

## 配置项

`config.json`（首次运行自动生成，修改端口后重启生效）：

```json
{ "port": 8902 }
```

AI 配置在应用内「⚙ API」中填写（也可直接编辑）：

```json
{
  "port": 8902,
  "ai": { "baseURL": "https://api.deepseek.com/v1", "model": "deepseek-v4-flash", "apiKey": "sk-…" }
}
```

## 排障指南（FAQ）

| # | 现象 | 可能原因 | 解决方案 |
|---|------|---------|---------|
| 1 | 双击 start.bat 提示未检测到 Node.js | 系统 PATH 中没有 node | 启动器会自动回退到 Trae 内置 Node（`%USERPROFILE%\.trae-cn\binaries\node\versions\*`）；若仍提示，说明该路径也不存在，运行 `winget install OpenJS.NodeJS.LTS` 安装后重试 |
| 2 | 提示端口 8902 被占用 | 上次进程残留或端口冲突 | 修改 `config.json` 的 port；或结束占用进程后重试 |
| 3 | 页面中文乱码 | 系统编码问题 | 确认启动器正常生成 UTF-8 文件；重新双击 start.bat |
| 4 | 数据「加载失败」 | data 文件损坏 / 服务未启动 | 确认服务在运行；损坏时删除 `data/投递数据.json` 后重启（会重建空表） |
| 5 | 保存时提示失败 | 数据目录只读 | 检查 `data/` 目录写权限 |
| 6 | 浏览器未自动打开 | 系统禁止自动打开浏览器 | 手动访问 http://127.0.0.1:8902 |
| 7 | 置顶后刷新消失 | 未写入成功（磁盘满/只读） | 看右上角状态是否「已保存」；磁盘空间不足时清理后重试 |
| 8 | 搜索不到记录 | 关键词大小写/全半角 | 使用公司名或岗位关键词（忽略大小写）；清空筛选条件重试 |
| 9 | 面试提醒不准 | 时区/面试时间未填 | 确认该岗位填写了「面试时间」；系统按本地时区判断 ≤24h |
| 10 | 秋招 Tab 为空 | 该岗位工作类型非「秋招」 | 新增时工作类型选「秋招」，或在更新中修改工作类型 |
| 11 | Offer Tab 为空 | 尚无拿到 Offer 的投递 | 在「更新」中把结果标记为 Offer 后即出现在该 Tab |
| 12 | 关掉窗口后数据还在吗 | 数据已落盘 | 在，数据保存在 `data/投递数据.json`，重新启动即可 |
