# JS-Agent 前后端规则对齐说明（企业类型多选 × 数量生成）

> 版本：v1.0 · 2026-08-17
> 适用范围：JS-Agent「岗位匹配」功能 —— 前端提交参数与后端解析/过滤规则的全链路契约
> 维护提示：任何一侧改动前，先读本文档；改完同步更新，保持两端枚举一致

---

## 1. 链路总览

```
前端 index.html（控件定义）
  → 前端 app.js startMatch()（收集 + 提交 body）
  → 后端 api/match.py（参数校验 + 透传）
  → 后端 agent/loop.py（前端勾选 ∪ 画像推断 → 归一化 → selected_types）
  → 后端 core/gates.py CollectionGate.judge()（企业类型过滤）
  → 输出岗位清单
```

数量参数平行走：`前端 maxResults select → body.max_results → match.py 校验 → loop.py 截断`

## 2. 企业类型多选：前端 → 后端对照表

| 环节 | 文件 | 代码 | 值域 |
|---|---|---|---|
| 控件定义 | `frontend/index.html` L115-L121 | `#companyTypes` chips，5 个 checkbox | 央企 / 国企 / 大型 / 中型 / 小型（默认全勾） |
| 前端收集 | `frontend/js/app.js` L214 | `querySelectorAll("#companyTypes input:checked")` 取 value | 勾选项数组（可空） |
| 前端提交 | `frontend/js/app.js` L226 | `body.company_types = types` | JSON 数组 |
| 后端校验 | `app/api/match.py` L62 | `req.get("company_types") or []` | 透传，无枚举校验（校验在 loop 内） |
| 合并画像 | `app/agent/loop.py` L208 | `list(dict.fromkeys([*frontend_types, *card["company_types"]]))` | 前端 ∪ 画像推断 |
| 归一化 | `app/agent/loop.py` L210-L211 | 覆盖全部 5 类 → 置空 | 全选 = 不限 |
| 过滤执行 | `app/core/gates.py` L146-L153 | `etype not in selected_types` → excluded | 严格过滤，含「未知」 |
| 收录兜底 | `app/agent/loop.py` L172-L179 | `_collect_mode` | scout 模式也尊重 excluded |

### 2.1 过滤集合计算（loop.py 内，顺序敏感）

```python
frontend_types = request.get("company_types") or []            # 前端勾选，空=不限
selected_types = list(dict.fromkeys([*frontend_types, *card.get("company_types", [])]))  # 前端 ∪ 画像推断
if selected_types and set(selected_types) >= set(ALL_COMPANY_TYPES):
    selected_types = []                                        # 归一化：全选 = 不限
```

**关键规则：**
1. 前端勾选是**硬约束**；画像文本声明（如"想进国企"）作**补充**，两者取并集
2. 画像推断 `card["company_types"]` 只保留 LLM 明确推断值；未声明 → 空列表（`gates.py` 默认值已是 `[]`）
3. 并集覆盖全部 5 类 → 归一化为空 = 不限（前端默认全勾，不应误伤「未知」类型岗位）

### 2.2 勾选状态 × 过滤行为矩阵

| 前端勾选状态 | 画像推断 | 归一化后 selected_types | 过滤行为 |
|---|---|---|---|
| 默认全勾（5 类） | 任意 | `[]` | 不限，所有类型保留（含「未知」） |
| 全不勾选（`[]`） | 无 | `[]` | 不限 |
| 全不勾选（`[]`） | 有（如 `["国企"]`） | `["国企"]` | 仅国企；未知排除 |
| 部分勾选（只勾"央企"） | 无 | `["央企"]` | 仅央企；未知排除 |
| 部分勾选（只勾"央企"） | 有（`["国企"]`） | `["央企","国企"]` | 央企 ∪ 国企；未知排除 |

## 3. 数量生成：前端 → 后端对照表

| 环节 | 文件 | 代码 | 值域 |
|---|---|---|---|
| 控件定义 | `frontend/index.html` L108-L110 | `#maxResults` select | 10 / 20 / 30 / 40 / 50 / 100（默认 20） |
| 前端提交 | `frontend/js/app.js` L226 | `max_results: Number(maxResults)` | 数字 |
| 后端校验 | `app/api/match.py` L39-L41 | `int(...)` + `not in (10,20,30,40,50,100)` → 400 | 枚举强校验 |
| 最终截断 | `app/agent/loop.py` L350 | `final_entries[:max_results]` | 排序后取前 N |

**规则：** 前端 select 值与后端校验集合**必须一致**，改动任一侧需同步另一侧（见 §6）。

## 4. 相关常量与枚举（四处必须一致）

| 位置 | 枚举内容 | 用途 |
|---|---|---|
| `frontend/index.html` L115-L121 | 央企 / 国企 / 大型 / 中型 / 小型 | 前端 chips |
| `app/core/schema.py` L27-L30 | `company_types.items.enum` 同 5 类 | 画像卡 JSON Schema 校验 |
| `app/agent/loop.py` L33 `ALL_COMPANY_TYPES` | 同 5 类 | 归一化（全选判断） |
| `app/core/schema.py` L47 `enterprise_type.enum` | 5 类 + 未知 | 岗位条目 Schema（未知是 classifier 兜底） |

> `app/core/enterprise.py` classifier.classify() 返回 **6 值**：央企/国企/大型/中型/小型/未知。「未知」不在前端 chips 中，但会在过滤时被排除（见 §2.2）。

## 6. 维护注意事项

1. **增删企业类型档位**：需同步改 4 处（§4 表格），并更新 §2.2 矩阵
2. **改动数量档位**：前端 select 和后端 match.py 校验集合必须同时改
3. **画像推断语义**：prompts.py 与 gates.py 默认值强耦合——prompt 让 LLM 输出什么，gate 的兜底默认值就要对应；当前约定「未声明 → `[]`」
4. **测试入口**：`tests/test_gates.py`（企业类型过滤单元测试，含未知/不限/合并 3 个场景）；改过滤逻辑先跑 `python -m pytest tests -q`
5. **模式差异**：`mode=scout`（默认）与 `mode=match` 的收录门槛不同，但企业类型/时效硬过滤两者都生效
