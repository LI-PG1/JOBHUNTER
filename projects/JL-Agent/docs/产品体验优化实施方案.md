## 一、目标与原则

1. **主线化**：用户一进页面就知道「从哪开始、现在在哪、下一步做什么」，全旅程（配置 → 填简历 → 生成 → 预览/编辑）有一条清晰的步骤主线。
2. **信息分级**：必填一眼可见，可选/高级收敛折叠，重要操作有醒目标注，同质化提示消除。
3. **成功路径**：每个关键动作后都有明确反馈与下一步引导（示例数据、完成滚动、空状态指引、编辑提示可见）。
4. **语言与可访问性**：术语人话化；键盘可达；窄屏不重叠不挤压；不引入构建、不改后端契约、不动数据层。

**硬性边界（勿越）**：
- 只改 `frontend/index.html`、`frontend/css/app.css`、`frontend/js/app.js`、`frontend/js/adapt.js`；
- 不改后端 API、字段契约（docs/contract.md）、生成引擎、数据存储；
- 不引入 npm/构建工具，保持零构建原生 HTML/CSS/JS；
- 版本号仍由 `app/version.py` 单点维护；本次为体验优化，可在完成后发布 v0.6.1（由作者决定，不自行推送 Release）。

- JS（`frontend/js/app.js`）注入步骤状态联动 `window.stepUI(n, "active"|"done")`：
  - `saveSettings()` 成功分支（约 531 行 `hint.textContent = "已保存…"` 处）→ `stepUI(1,"done")`；
  - `saveResume()` 成功分支（约 382 行 `req.then` 后）→ `stepUI(2,"done")`；
  - `startGenerate()` 提交处 → `stepUI(2,"done")`、`stepUI(3,"active")`；

  - `stepUI` 实现（原生 JS）：
  ```js
  window.stepUI = function (n, st) {
    var li = document.querySelector('.progress-steps li[data-step="' + n + '"]');
    if (!li) return;
    li.classList.remove("active");
    if (st === "done") li.classList.add("done");
    else if (st === "active") li.classList.add("active");
  };
  ```

## 五、最终 E2E 验收清单（全阶段完成后统一执行）

1. 打开面板：三栏布局正确，左步骤条 ① 高亮，右栏显示「开始前必读」；
2. 打开 ⚙ 高级设置 → 新增配置 → 保存并自检：抽屉可 Esc 关闭；验证主卡片「保存并自检」流程正常；
3. 主卡片填配置名/模型/接口地址/Key → 保存并自检成功：步骤 ① 变 done、② 变 active；settings-status 变绿；

5. 生成卡片：页数/水印/深度搜索均有说明；点「简历生成」：进度条推进；完成后自动滚动到预览、编辑提示高亮、步骤 ③ 变 done；
6. 预览：点击正文文字可编辑，保存后条目带「已锁定」；导出按钮可用；
7. 新建简历：清空表单，「我的简历」回到空状态指引；

9. 窄屏（720px/1024px/1440px）三档走查：无重叠、无横向滚动条；
10. 回归：`tests/smoke_api.py`（若可运行）不因前端改动受影响——前端改动不碰 API，此步仅确认服务可起。
