## 三、内部实现机制七维度审查（任务 2）

### 3.1 prompt 注入机制
- ✅ **修复后防线**：system 角色（SYSTEM_GEN/SYSTEM_CHECK）+ 数据定界符（【】区块）声明"数据非指令"；上下文快照 `_上下文快照.md` 完整落盘供溯源。
- ⚠️ 遗留：`_上下文快照.md` 本身是"注入面"落盘物（含用户数据），仅本地自用，风险可接受；未做"system 提示词可配置化"。
- 结论：JD/简历/参考信息夹带"忽略上述指令"式注入已被 system 声明与定界符双重抑制。

### 3.2 HTML 生成模块（build.js）
- ✅ 格式规范：Markdown → HTML 渲染器支持标题/表格/列表/引用/代码块/术语 tooltip/折叠面板/笔记，样式统一（CSS 变量 + 响应式 + 移动端步骤条）。
- ✅ 本轮修复：章节缺失不再静默（SKIPPED 进横幅 + verify 白名单 FAIL）。
- ⚠️ 遗留：`annotateText` 在 `escapeHtml` 之后做术语高亮，术语含 HTML 元字符时的转义完整性缺一条 verify 断言（建议批次二）。

### 3.3 模块间数据传递
- ✅ 任务输入经 `input` 快照保存，retry 复用（resumeText/jdText 回写防丢失）；解析/抓取结果落盘 `_上下文快照.md` 防中断丢失。
- ✅ SSE 事件流统一 `pushEvent` 快照 + 广播，客户端断连不阻断任务。
- ⚠️ 遗留：`t.events` 无上限（长任务 + 多 log 内存线性增长，建议上限 2000 条滚动截断）；SSE 重连客户端全量重放历史事件。

### 3.4 配置参数验证
- ✅ 岗位名白名单正则（路径注入防护）、resumeVer A/B 校验、urls ≤20 条、refInfo ≤20000、jdText/resumeText ≤20000、跨站 Origin 校验 + Content-Type 校验。
- ⚠️ 遗留（次要）：`config_api.js` 允许 apiKey ≥5 字符可保存 vs `llm_gateway.availableProviders` 要求 >10 字符（不一致但均有兜底提示）；`maxOutputTokens` 无类型校验；`enabled` 对字符串 "false" 判真。建议批次二统一阈值与类型收口。
- ⚠️ 遗留：CAP_MAP 三选项（textvision/multimodal/textocr）映射同值 `["text","vision"]`，UI 存在误导（无纯 OCR 选项），建议合并为"文本+视觉"单选项。

### 3.5 日志记录系统
- ✅ 任务级 log 事件全量推送前端日志框；构建/校验子进程输出回传；uncaughtException/unhandledRejection 进程级兜底不退出。
- ⚠️ 遗留：`uncaughtException` 仅记 message 无 stack，排查困难；日志未落盘文件（重启即失）；建议批次二：日志文件（如 `00_规范/logs/`）+ stack 全量 + 滚动策略。

### 3.6 错误处理覆盖度
- ✅ 覆盖：创建校验 400 / 并发互斥 409 / 终态不可取消 409 / SSE 断线自动重连 / 单文件失败不阻断 / build/verify/check 三级尽力而为 / 取消即时生效（P1-3/P1-5 状态守卫）。
- ✅ 本轮修复：runChild 超时兜底、取消后 retry 重建 signal、前端错误恢复按钮、`humanTestError` 中文可操作提示。
- ⚠️ 遗留（次要）：`humanTestError` 已用于 Key 保存/自检，但任务创建失败等链路仍展示原始英文；重试成功后前端不刷新任务徽章；SSE onerror 空实现导致日志区重复追加。建议批次二。

### 3.7 核心算法效率与准确性
- ✅ 上下文裁剪：urls 逐条 8000 / 15 条 / 总量 50000 + refInfo 20000 + 本轮 JD/简历 20000 统一；8 文件串行生成 + max_tokens 超限自动减半降级 + provider 失败自动切换。
- ✅ 术语高亮单次正则编译（TERM_RE 缓存）；平衡括号扫描解析超长 JSON（verify 修复 E）。
- ⚠️ 遗留：8 文件串行串行为已知性能瓶颈（全流程 3~10 分钟），批次二建议限流并行（2~3 并发）+ 上下文按文件裁剪。

## 五、遗留次要项（建议批次二）

1. 错误人性化：`humanTestError` 应用于任务创建/取消等全链路。
2. 误导性徽章：文件失败统一显示"verify FAIL"较粗糙，建议区分"build 失败/verify 失败/章节缺失"。
3. SSE 断线提示 + 日志去重（onerror 空实现）。
4. 重试成功后界面刷新（任务徽章/文件列表同步）。
5. 简历上传键盘可达性（drop 区不支持键盘触发）。
6. `config_api` 校验收口：apiKey 阈值统一、maxOutputTokens 类型、enabled 布尔化、CAP_MAP 合并。
7. IPv6 内网段（ULA/link-local）未覆盖 `isBlockedHost`。
8. `t.events` 数组封顶（2000 条滚动）+ 日志落盘（文件 + stack）。
9. 8 文件限流并行（2~3 并发）+ 上下文按文件裁剪。
10. verify 增加"术语含 HTML 元字符时转义完整"断言。
