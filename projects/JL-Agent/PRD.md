## 1. 产品定位

**一句话**：用户提供少量信息（个人背景 + 目标岗位 JD），简历生成助手 一键生成一版完整、专业、可打印、**页面填满无大面积空白**的简历（**HTML 格式，支持分页控制**）。

**差异化**：聚焦"缺少经历的用户"——既能美化真实经历，也能按岗位方向生成式创造**项目经历**（不创造实习经历）；多岗位 JD 输入（同一职业方向），生成综合定制版简历；**动态排版适配**保证任意内容配置下页面布局协调。

**两个版本**：实习版 / 秋招版（页面勾选切换）。两者仅细节差异、无本质区别，先实现实习版，再基于同一套代码扩展秋招版。

**独立 Agent**：现阶段简历生成功能作为独立 Agent 开发，**暂不考虑与 MS-Agent 的集成**（含接口对接、数据文件交换、导入导出）。

---

## 2. 目标用户与使用场景

| 用户画像 | 核心痛点 | 简历生成助手 提供的价值 |
|---|---|---|
| 在校学生/应届生（实习求职） | 缺乏实习与项目经历，简历单薄 | 生成式**项目经历**创造、美化扩写（实习经历不创造） |
| 有经历但表达不专业的求职者 | 经历写得平淡、不量化 | AI 美化润色、专业结构化 |
| 同方向多岗位投递的求职者 | 不同 JD 需要适配同一份简历 | 同一职业方向多岗位 JD 输入，综合版简历自动整合 |
| 需要打印投递的求职者 | 简历打印格式不规范、页面留白难看 | HTML 分页 + 一页/两页选项 + **动态适配填满页面** |

## 3. 功能需求

### 3.1 前端（原生 JS 零框架，无构建步骤，延续 MS-Agent 风格）

#### 3.1.1 版本切换
- 页面提供"实习版 / 秋招版"勾选切换（先实现实习版，秋招版字段扩展预留）。
- 切换影响：提示文案、部分字段标签/提示、生成 prompt 的版本指令、身份设定（实习生/全职）；**数据结构保持不变**。

#### 3.1.2 基础信息模块（必填 + 照片）
| 字段 | 说明 |
|---|---|
| 姓名 | 必填 |
| 年龄 | 必填 |
| 邮箱 | 必填，格式校验 |
| 电话 | 必填，格式校验 |
| 个人网页 | 选填 |
| base（意向城市） | 选填 |
| 可实习时长 | 选填（实习版）/ 全职入职时间（秋招版） |
| 到岗时间 | 选填 |
| **照片** | 选填，见 §3.1.7 照片上传 |

> **说明**：简历中**不展示"目标岗位/职业方向"字段**（用户一对一投递，该信息已体现在求职信/投递信息中）；职业方向仅作为生成引擎的上下文输入，不显示在简历成品中。

#### 3.1.3 教育经历（必填）
- 字段：学校名称、专业名称、学位类型（学士/硕士/博士…）、起止时间（**精确到月**）。
- 展示格式示例：`企鹅大学 计算机科学与技术 工学硕士 2025.09—2029.06`
- **交互**：默认显示 1 条填写栏；提供"+"号按钮添加额外经历；**最多支持 3 段**（覆盖本科+硕士+博士场景），达到上限后"+"禁用并提示。
- **严格数据校验**：
  - 时间格式必须为 `YYYY.MM`；
  - 结束时间必须晚于开始时间；
  - 学位类型必须为合法枚举；
  - 教育经历至少 1 条（必填模块）。

#### 3.1.4 附加信息模块
- **实习经历**（选填，**最多 2 段**）：公司名称、职位、时间段、主要职责与成果。默认显示 1 条填写栏，提供"+"号添加，**最多支持 2 段**（达到上限后"+"禁用并提示）。**未填写时，简历成品自动隐藏"实习经历"区块**。
- **项目经历**（选填，可多条）：项目名称、角色、时间段、技术栈、项目描述、个人贡献。
- **技能特长（必填）**：
  - 用户必须输入至少一类技能内容（表单必填校验）；
  - **相关性校验（定稿规则）**：防止用户输入与岗位方向完全无关的内容（如 JD 是 AI 开发、技能填"会计做账"）。
    - 判定：LLM 打分制——将「用户技能列表 + 岗位方向/JD 关键词」送入 LLM，输出相关度 0~1 分与理由；
    - 阈值：**≥0.6 通过**；**0.3~0.6 弱相关**，提示"技能与岗位方向关联较弱，建议补充相关技能或调整表述"；**<0.3 完全无关**，阻止提交并建议修改；
    - 兜底：关键词匹配——JD 提取的硬技能词与用户技能词做交集，交集为空且 LLM 打分 <0.3 时判定无关（防 LLM 误判）；
    - 判定规则独立为规则文件，可迭代（版本化）。
  - **技能拓展勾选项**：用户可选择开启——
    - 开启：系统根据用户提供的职位描述（JD）对技能进行必要补充；
    - 补充内容保持**客观真实**，仅做必要能力补充，**避免过度夸张**；
    - 未开启：系统仅对用户提供的技能做**专业分类与优化排版**，不新增内容。
- **获奖荣誉**（选填，可多条）：奖项名称、颁发机构、获得时间。**可选区块，可动态显隐**（见 §6.7）。

#### 3.1.5 岗位 + JD 填写模块（参考 MS-Agent）
- 默认展示 1 套（岗位名称 + 对应 JD 文本），一套为一个模块化组件。
- 点击"+"动态新增同构模块；**最多 5 套**（到达上限后"+"禁用并提示）。
- 每套可单独删除；JD 支持粘贴文本（参考 MS-Agent 的 JD 文本输入方式）。
- **引导用户上传同一职业方向的多个岗位 JD**（同方向便于综合提炼核心技能与经历整合）。

#### 3.1.6 生成模式、分页与进度展示
- **生成模式**：单一职业方向的**综合版本**简历（一次生成）：
  - 支持在同一职业方向下输入多个岗位（相同或不同公司、相同或不同岗位），系统生成**一份综合简历**；
  - 职业方向可适当宽泛但须保持**主题一致性**；内容侧重由系统**根据用户上传的岗位与 JD 分析结果自动确定**，不预设固定倾向；
  - **禁止跨领域**：不允许同时生成完全无关领域的岗位内容（如 AI 开发工程师 + 会计），提交时执行**主题一致性校验**，跨领域时提示用户调整岗位组合；
  - **主题一致性校验（定稿规则）**：领域标签法 + LLM 语义兜底——
    - LLM 为每个岗位提取领域标签（如 AI/后端/数据/前端/算法/产品/运营…），所有岗位**共享 ≥1 个领域标签**即判定同域、允许生成；
    - 无共享标签时用 LLM 语义相似度兜底：岗位两两相关度 ≥0.4 视为同域可合并；<0.4 判定跨领域，阻止生成并提示用户调整岗位组合；
    - 判定规则独立为规则文件，可迭代（版本化）。
  - 生成时对各岗位技能/经历做整合，提炼共同核心能力。
- **分页选项**（用户选择）：
  - `一页简历`：高密度布局，突出核心信息，内容结构精简；
  - `两页简历`：宽松布局，可容纳更多详情。
  - 不同分页选项对应不同的**内容结构算法与信息稠密程度**（见 §6.4）；最终输出通过**动态适配**确保页面填满（见 §6.7）。
- **一键生成与进度展示**（学习 MS-Agent 生成部分）：
  - 页面下方展示生成进度（阶段进度条 + 阶段文案）；
  - 任务状态机（pending → analyzing → generating → building → done）+ SSE 实时进度推送；
  - 生成完成后展示 **HTML 预览**，支持分页打印；HTML 版成熟稳定后启用 PDF 导出（阶段化，见 §3.1.9）。

#### 3.1.7 个人照片上传（数值定稿）
- **格式限制**：支持 JPG、PNG（拒绝 GIF/动图、WebP）。
- **尺寸限制**：最小像素 **≥200×200**（过低无法清晰打印），最大像素 **≤4000×4000**（过大浪费内存），超限给出明确提示。
- **文件大小**：**≤5MB**，超限提示压缩后再传。
- **比例限制**：推荐证件照宽高比 **3:4**（次选 4:5），不符合时提示（不强制拦截）。
- **位置预设**：简历模板预设照片区域，位于**页面右上角**（专业简历规范位置，已定稿）；上传后自动裁剪/适配显示；**未上传则区域默认隐藏**（不留空位、不破布局）。
- 上传后支持预览与替换。

#### 3.1.8 前端统一布局与交互（参考 MS-Agent 设计风格）
- **表单分区设计**：按模块分区（基础信息 / 教育经历 / 附加信息 / 岗位 JD），必填与选填字段用视觉区分（参考 MS-Agent 的 `.req`/`(可选)` 标注体系）。
- **进度条样式**：参考 MS-Agent 8 步固定权重进度条（阶段化 + 百分比推进）。
- **操作反馈机制**：保存/生成/失败均以 toast 反馈（规避同步弹窗卡死问题，参考 MS-Agent v0.3.3 修复）；错误提示字段级化、中文可读。
- 整体视觉与 MS-Agent 保持一致（配色/间距/卡片风格），确保两产品体验连贯。

#### 3.1.9 PDF 导出（阶段化后置，v0.6 定稿）
- **前置条件**：HTML 版（含动态适配、分页控制、打印样式）**成熟稳定后**才启动 PDF 导出功能，不挤占 HTML 主线开发。
- **方案研究任务（开发期执行）**：对比并评估候选方案——
  1. 浏览器原生打印/另存为 PDF（Ctrl+P）：零依赖、保真度高，但分页/样式依赖用户浏览器与设置；
  2. 无头渲染（Playwright / 无头 Chrome）：样式与分页可控、可一键导出，依赖较重；
  3. 纯库渲染（WeasyPrint / pdfkit 等）：中文排版与复杂 CSS 需实测验证；
  4. 前端方案（html2pdf.js 等）：集成简单，复杂布局保真度需实测。
- **评估维度**：中文渲染质量、分页一致性（与 HTML 版结果一致）、ATS 保真、依赖复杂度、本地单用户场景维护成本。
- **落地倾向（待评估确认）**：默认引导用户使用浏览器原生打印另存为 PDF；无头渲染作为"一键导出 PDF"增强选项，是否启用以评估结论为准。
- 配套 API：`GET /api/export/pdf`（§5）。

### 3.2 后端 API 服务

- 简历信息 **CRUD**：基础信息 / 教育经历 / 附加信息（实习、项目、技能、获奖）的增删改查。
- **照片上传**接口：校验格式/尺寸/比例，保存并返回预览地址。
- 生成任务接口：创建生成任务（含分页选项参数）、查询任务状态/进度、取消任务、获取结果。
- 生成式**项目经历**接口：按用户输入（或完全无输入）+ JD + 联网数据生成项目经历（STAR 自然段落）。
- **技能拓展/校验**接口：技能相关性校验、按 JD 技能补充（可选增强）。
- 美化/润色接口：对用户真实经历（含**实习经历**，仅美化不创造）进行专业优化。
- 质量评估接口：对生成内容做一致性/专业性检查（对标 MS-Agent verify/check 的轻量版）。
- 搜索管理接口：搜索模式状态查询、BrowserSkill 深度取材调用（见 §3.6）。

### 3.3 简历生成助手 核心特色功能（经历生成与优化引擎）

1. **经历生成引擎**（核心差异化）：
   - **项目经历**：
     - **有项目输入**：基于分析结果进行内容优化、突出相关经验、调整呈现结构（不改变事实，仅优化表达与侧重）；
     - **无项目输入**：根据岗位方向生成合理的项目经历（如 AI Agent 开发方向可生成"智能客服 Agent 系统"、"多模态竞品分析 Agent"等专业项目名称），AI 完全创造（用户已明确决策）；
     - 输出遵循 **STAR 法则**（情境-任务-行动-结果），但**在简历成品中不显示 S/T/A/R 标识或标题**，将法则融入自然段落描述。
   - **实习经历**：**只提供美化，不提供创造**——对用户真实实习经历做语言润色、结构化、量化建议（不改变事实）。
   - **美化提示词差异化**：实习经历与项目经历的美化提示词**既有区别又有联系**——共用"结构化表达/量化建议/突出相关经验"的原则，区别在于：实习经历强调真实职责还原与成果量化；项目经历额外支持按 JD 方向调整技术方案描述与角色侧重（创造场景）。
   - 输入：基本信息、教育经历、可选经历片段、岗位 JD 分析结果、联网搜索资料、生成规则、身份（实习生/全职）。
2. **岗位 JD 分析与项目匹配**：
   - 对用户上传的所有岗位信息和 JD 内容进行**联网搜索与深度分析**，提取关键技能要求、任职资格和行业标准；
   - **职业方向主题一致性校验**：检测多岗位是否属同一职业方向，跨领域（如 AI 开发 + 会计）时阻止生成并提示用户调整岗位组合；同领域岗位允许生成，内容侧重由系统根据 JD 分析结果自动确定（不预设固定倾向）；
   - 基于 JD 分析结果匹配相关项目类型，生成行业规范的专业项目（如 AI Agent 开发方向 → 智能客服/竞品分析 Agent 等）；
   - 通过联网搜索获取**真实生产环境中类似项目的实施流程、技术栈和关键成果指标**，增强真实性；
   - 根据用户背景（专业、技能水平）微调内容，按身份差异化调整责任描述与成果占比。
3. **身份差异化规则**：
   - **实习生**：强调学习过程、辅助任务、团队协作，成果占比侧重学习成果和辅助贡献；
   - **全职**：突出独立负责模块、技术决策、业务影响，成果占比侧重业务产出。
4. **技能特长处理**（结合 §3.1.4）：
   - **相关性校验**：校验用户技能与岗位方向的关联度，完全无关时提示修改；
   - **技能拓展**（用户勾选时）：系统按 JD 提取所需技能，对用户技能做必要补充；补充内容客观真实、不过度夸张，且需可被用户确认；
   - **分类优化**（未勾选时）：仅对用户技能做专业分类（专业技能/工具/语言）与优化排版。
5. **联网搜索模块（双模设计）**：
   - **默认：API 搜索**（Tavily / 免费 Serper）：常规关键词检索，轻量、无外部依赖；用于行业信息、技术方向、岗位常用技能、真实项目案例、公司动态等。
   - **可选：BrowserSkill 深度取材模式**（默认关闭，用户手动开启）：
     - 针对 API 拿不到的平台内容（知乎、小红书、抖音等需登录/强反爬站点）与动态渲染页面；
     - **BYO 账号**：使用用户自己已登录的浏览器（通过腾讯 BrowserSkill 的 `bsk` CLI + 浏览器扩展接入），开发者不持有任何账号；
     - **Human-in-loop**：验证码/滑块/登录确认时暂停，交用户手动处理；
     - **边界约束**：不内置任何平台逆向代码（仅通用浏览器操作）；固定限频策略（用户不可修改）；抓取内容仅作生成上下文、不落库不存储不导出；界面明示免责声明（账号风险自担、仅供个人学习）；
     - 若用户环境未安装 BrowserSkill（CLI/扩展/daemon 缺失），该模式自动提示缺失并降级为 API 搜索，不阻塞主流程。
   - 搜索失败不阻塞主流程（降级为纯 LLM 生成，AI 按【待联网核实】协议标注，参考 MS-Agent v0.4.9 方案）。
6. **经历美化功能**：对用户真实经历（实习/项目）做语言润色、结构化、量化建议（不改变事实，仅优化表达）。
7. **生成式项目经历库**：预置符合行业规范的项目模板/案例库，用户可挑选后由引擎生成个性化版本。
8. **项目经历生成规则引擎**：规则集中配置、可迭代（规则文件独立于代码，后续可扩展）。

### 3.4 与 MS-Agent 集成

- **现阶段不集成**（用户决策）：简历生成功能作为独立 Agent 开发，暂不考虑接口对接、数据文件交换及导入导出。
- 预留：数据结构设计保持清晰可导出（JSON），为未来可能的对接保留可能性，但不做集成开发。

### 3.5 简历生成标准化流程（SOP 设计）

1. **固定简历整体架构模板**，核心板块包括（不限于）：个人信息、自我评价、教育背景、实习经历（可隐藏）、项目经历、技能特长、证书荣誉（可隐藏）。
2. **每个分区设计标准化内容架构与呈现格式**（组件化提示固化，参考 MS-Agent 的 components 机制）：
   - 个人信息：固定字段布局 + 照片位（右上/左上），无目标岗位展示；
   - **自我评价**（弹性内容）：一句话定位 + 核心优势；1~3 行弹性（引擎按剩余空间调整行数，见 §6.7）；
   - 教育背景：时间倒序、格式统一（1~3 条，固定内容）；
   - 实习经历：真实职责 + 量化成果，仅美化不创造（未填自动隐藏）；
   - 项目经历：STAR 融入**自然段落**（无 S/T/A/R 标识），量化口径规范、身份差异化；
   - 技能特长：**必填**、分类（专业技能/工具/语言）、按 JD 匹配度排序；
   - 证书荣誉：名称/机构/时间（可选区块，可动态显隐）。
3. **模板化生成机制**：静态骨架 + 内容注入（参考 MS-Agent 的 `skeleton.html` + build.js 装配模式），降低使用成本、提高生成速度；内容未变时支持增量缓存（可选优化）。

### 3.6 BrowserSkill 功能管理系统（参考 MS-Agent「高级设置」管理台）

1. **管理台界面**，包含：
   - **API 密钥配置界面**（搜索服务 Key，脱敏存储与展示，参考 MS-Agent maskKey 思路）；
   - **技能（Skill）管理模块**：BrowserSkill 安装状态检测（CLI/扩展/daemon 三件套）、安装引导、状态展示；
   - **CLI 工具配置选项**：相关本地工具探测与配置（参考 MS-Agent `/api/cli-tools` 模式）。
2. **BrowserSkill 深度取材交互入口**：
   - 设置项开关（默认关闭）；
   - 环境检测提示（缺失依赖时给出安装引导，不阻塞主流程）；
   - 免责声明文案展示（账号风险自担、仅供个人学习）。
3. **固定限频策略（数值定稿）**：采用固定数值（不提供用户修改权限），确保系统安全性与账号安全——
   - BrowserSkill 深度取材：单次生成任务内**累计请求 ≤20 次**、两次请求**间隔 ≥20s**（HITL 人工处理等待不计入）、**单日累计 ≤60 次**；
   - API 搜索：沿用服务商免费额度节奏（Tavily 免费 1000 次/月，查询间隔 ≥1.1s 防 429）；
   - 达到限频上限后本任务自动降级为 API 搜索 / 纯 LLM 生成，不阻塞主流程。
4. **限频策略的优劣说明**（向用户明确展示）：开启深度取材可能降低生成速度，但会提升内容准确率与信息质量，建立用户对功能的合理预期。

### 3.7 系统初始化流程（首次使用引导）
1. **第一步：配置 API 密钥**（保留为核心引导，参考 MS-Agent 初始化）：引导用户填写文本模型 API 密钥（**界面文案不展示具体模型名**；系统内部按默认推荐模型配置——设计参考：DeepSeek-V4-Flash，低成本高吞吐，支撑高精度预算与多轮迭代生成，无需为调用成本做轻量化妥协）；同时支持用户提供多模态模型 API（可选增强）。
2. **能力检测**：配置后自动检测——
   - 文本模型连通性（真实最小请求自检，参考 MS-Agent `/api/providers/:name/test` 思路）；
   - 视觉能力来源：优先检测多模态模型 API（若有），否则检测**视觉 CLI 工具**（如 OCR 工具链）是否可用。
3. **功能实现原则**：核心功能基于**文本模型生成能力 + 视觉 CLI 工具**共同完成（不依赖多模态模型即可全功能运行，多模态为可选加速/增强，参考 MS-Agent-Lite 思路）。
4. 检测结果分级提示（可用 / 缺失并给出安装引导），不阻塞后续使用。

## 6. 生成引擎设计（概述）

### 6.1 主流程
收集信息（表单 + 照片 + 联网搜索）→ 岗位 JD 分析与联网深度分析 → 组装上下文（基本信息/教育/经历/JD 分析结果/行业资料/生成规则/身份）→ 结构化生成（按模块，STAR 自然段落）→ 质量检查 → 用户预览/编辑 → **动态适配** → 按分页选项渲染 HTML。（流程层面的并行/增量/失败隔离等优化决策见 §6.1.1。）

### 6.1.1 流程反思与优化（v0.5 增补，第五轮）

从 0 审视 §6.1 主流程后，识别并决策以下优化项（**"采纳"项进入开发清单**，落地时按对应落点章节实现）：

| # | 现状问题 | 优化方案 | 决策 | 落点 |
|---|---|---|---|---|
| 1 | 分块生成串行；自我评价/教育/技能等板块本不依赖 JD 深度分析 | **分层并行（任务 DAG）**：第一层 = JD 分析与联网搜索 + 独立板块（自我评价/教育/技能/实习美化）并行；第二层 = 依赖 JD 结果的板块（项目生成/技能拓展）；生成进度按板块粒度上报 | 采纳 | §6.1 / §3.1.6 |
| 2 | 多模块多次 LLM 调用，核心技能/量化口径/项目事实易互相矛盾 | **共享事实表（shared fact sheet）**：JD 分析产出唯一事实源（核心技能词、项目类型、量化口径、身份），所有板块生成统一引用，写入"组装上下文" | 采纳 | §6.1 / §6.10 |
| 3 | 质量检查（§6.5）在全部生成后全量再跑，WARN→重生成形成全量往返 | **自检前置 + 审阅降本**：生成 Prompt 内嵌自检指令（一次完成）；§6.5 保留为用户可见建议层，仅对 critical/high 项与溢出场景做复核，不自动全量重跑 | 采纳 | §6.1 / §6.5 |
| 4 | 动态适配靠"渲染→测量→压缩"事后收敛，最多 3 轮 | **内容侧约束量化（预算前置，高精度）**：生成前按目标页数可用高度为各描述性板块分配空间预算——采用**高精度预算模型**（模型篇幅自估 + 实测校准；默认生成模型 DeepSeek-V4-Flash 成本低，不设轻量约束，可支撑多次估算与校准迭代），生成即贴近目标；保留 ≤3 轮兜底 | 采纳 | §6.4 / §6.7 |
| 5 | 预览编辑或审阅重生成时，现状暗示全流程重跑 | **增量重生成 + 缓存**：只重生成目标板块；JD 分析结果与未变动板块结果缓存复用 | 采纳 | §3.1.6 / §6.1 |
| 6 | 适配压缩内容层时可能改动用户手动编辑的内容 | **编辑锁定**：用户手动编辑过的内容自动标记为 critical（不可裁剪/压缩），内容层调整只作用于 AI 生成项（ai-created / polished） | 采纳 | §6.5 / §6.7 |
| 7 | 单模块生成失败可能阻塞整条流水线 | **模块级失败隔离**：单模块重试 1 次，仍失败则输出简化版本并标注"待补充"，整单继续 | 采纳 | §3.1.6 / §6.1 |
| 8 | 适配微调重复全量重建 DOM | 仅切换 `body[data-density]` 与内容层配置，复用已渲染 DOM | 实现注意项 | §6.7 |

**不采纳（避免过度设计）**：
- 多用户并发/任务队列——本地单用户部署形态（§7）下明确不做；
- 取消用户可见审阅——保留 §6.5 建议层（供用户判断是否重生成）。

### 6.2 合规边界（用户已决策）
- 有用户经历（项目/实习）→ 基于真实输入美化（优化表达、突出相关、调整结构）；
- 无**项目**经历 → AI 完全创造（按岗位方向生成行业规范项目）；**实习经历不创造**；
- 技能拓展（勾选）→ 按 JD 必要补充，客观真实、不过度夸张；
- **量化数值直接生成（v0.6 决策）**：AI 创造内容中的量化数字**不再使用 `[X]%` 占位符**，由引擎直接生成合理数值——按行业口径与上下文取恰当数值与精度（精度规则见 §6.10 规则层）；把关改为：① 来源徽标 + ④ 导出确认清单（用户核对）+ §6.5 真实性审查（数值合理性、禁止极端值）。

### 6.3 内容创造风险缓解机制（具体形态）
完全创造内容必须带来源标记与确认关卡，把合规责任明确落到用户，同时保证面试场景可靠性。系统需在适当位置以明确形式显示提示："这部分内容不是你的真实经历，是 AI 生成的，需要你确认真实性"，在系统内显式区分"AI 创作内容"与"用户真实经历内容"。

**两种实现方案（用户提出）**：
- **方案一：独立配套说明文档**——与简历文件同时生成并交付，所有提示信息、免责声明及内容区分说明集中放置于该文档，用户可清晰查阅。
- **方案二：水印提醒必选开关**——强制选择项（未完成选择无法触发生成）：
  - `有水印`：结果文件中指定位置嵌入预设提示语句；
  - `无水印`：生成时立即向用户展示风险提示弹窗。

**PRD 采用：方案二为主 + 方案一为辅**：
- 主关卡采用方案二（必选开关保证"强制知情"，未选择不生成）；
- 辅助采用方案一（配套说明文档随简历一同交付，集中承载免责声明与内容区分说明）。

#### 6.3.1 风险缓解提示的落地形态（与两方案协同）
| 形态 | 说明 | 放置位置 |
|---|---|---|
| ① 来源徽标 | 每条 AI 创造的项目带 `AI 生成` 标签（区别于"用户提供/美化增强"），视觉弱化、不进入最终打印 | 项目卡片右上角 |
| ② 确认横幅 | 信息条：`以下 N 个项目为 AI 生成，请逐条确认真实性与细节后使用` | 编辑区顶部 |
| ③ 数值直接生成（v0.6 替换占位符） | AI 创造经历中的量化数字由引擎**直接生成合理数值**（精度按指标类型，见 §6.10 规则层）；数值合理性纳入 §6.5 真实性审查，并经 ① 来源徽标 + ④ 导出确认清单供用户核对 | 项目内容内 |
| ④ 导出前确认清单 | 导出弹窗列出所有 AI 生成项，需逐条勾选 `我已核对并确认真实性` 或选择 `仅用于自我练习` | 导出对话框 |
| ⑤ 免责声明 | `AI 生成的经历内容仅供求职准备参考，请在面试与投递前自行确认真实性` | 生成结果页脚 |
| ⑥ 练习模式导出 | 导出可选"练习版"（保留 AI 生成标记）或"正式版"（需完成 ④ 确认） | 导出选项 |

**文案定稿（v0.4）**：
- 有水印模式嵌入语句：「**本简历部分内容由 AI 生成，请确认真实性后使用**」
- 无水印模式弹窗文案：「**AI 生成的经历内容仅供求职准备参考，请在面试与投递前自行确认真实性**」
- 配套说明文档名称：《AI 生成内容说明与免责声明》（方案一辅助，随简历一同交付）

### 6.4 分页控制与信息稠密度算法

**常驻 / 非常驻板块分类（v0.5 定稿）**：
| 板块 | 分类 | 处理规则 |
|---|---|---|
| 个人信息（含照片） | 常驻 | 始终显示，不可删不可压 |
| 自我评价 | 常驻 | 始终显示；句数 1~3 句、内容层弹性（详略/句数）可调 |
| 教育背景 | 常驻 | 始终显示，1~3 条由用户决定 |
| 项目经历 | 常驻 | 始终显示（无输入时 AI 创造）；条数/要点数/详略（内容层弹性）可调 |
| 技能特长 | 常驻 | 必填始终显示；内容分类/JD 拓展由生成引擎决定 |
| 实习经历 | 非常驻 | 未填自动隐藏（**输入上限 2 段**）；显示时要点数/详略（内容层弹性）可调 |
| 证书荣誉 | 非常驻 | 未填或用户选择时隐藏 |

**分页控制逻辑**（目标页数 = 用户勾选，见 §6.7 页数判定）：
- **一页版**：常驻板块全部保留；非常驻板块仅当空间允许时显示且优先精简（实习 1~2 要点、证书荣誉仅最相关 2 条）；内容结构侧重"亮点优先"。
- **两页版**：常驻板块放宽（完整 STAR 自然段落、项目条数按下方硬性规则）；非常驻板块尽量全显示（实习全要点、证书荣誉全列）；必要时以 `.page-break` 强制分页（如技能区起第二页）。
- **数量硬性约束（v0.5 定稿）**：**项目条数**由「目标页数 + 实习经历条数」硬性决定，不随空间动态增减：

  | 实习经历条数 | 一页版项目条数 | 两页版项目条数 |
  |---|---|---|
  | 0（无实习经历） | 2 | 3 |
  | 1 | 1 | 2 |
  | 2 | 1 | 1 |

  - 实习经历**输入最多 2 段**（表单上限，§3.1.4），故表中实习条数最大为 2；
  - 逻辑：实习与项目为互补的描述性内容——实习越少、项目越多（无实习时项目补足内容量，有实习时项目让位）；
  - 约束优先于溢出压缩/不足扩充：压缩时**不减少项目条数**（只压缩每条要点数与详略），扩充时**不增加项目条数**（只增加每条要点数与详略），项目条数始终等于上表数值。
- **溢出压缩顺序**（从先到后）：按 criticality 从低到高裁剪非常驻条目（low→medium）→ 主导板块内容层降档（详细→标准→精简，减少要点/句数）→ 合并项目要点 → 精简自我评价（保留 critical 句）→ 排版层全局密度档（loose→normal→compact）→ 仍溢出则提示用户改选两页版。
- **不足扩充顺序**（从先到后）：追加自我评价句子（至 critical 句数上限）→ 主导板块内容层升档（精简→标准→详细，增加要点/技术栈详情）→ 排版层全局密度档（compact→normal→loose）→ 仍不足则提示用户改选一页版。

**信息稠密度算法（两层）**：排版层由全局 density 档（compact/normal/loose，字号/行距/间距/缩进全局统一，全部板块参与，参数见 §6.9）驱动；内容层由生成引擎按详略档（详细/标准/精简）与数量档（项目条数、要点数、自我评价句数）控制；由 §6.7 收敛流程（以关键路径为主导）在 3 轮内确定排版层档位 + 内容层详略/数量组合，输出最终密度配置。

### 6.5 批判性审阅与质量评估机制（critical review，v0.5 升级）

生成后以 **HR 视角批判性审阅**（critical review）对每个板块做审查，输出审查意见并驱动修订闭环（对标 MS-Agent verify/check 的轻量版）：
- **关键性审查**：每条内容是否达到其 criticality 等级预期——critical 项是否真实存在且与 JD 强相关，缺失则提示补充；
- **匹配度审查**：技能/经历与 JD 关键词覆盖率（<60% 提示补充或调整表述）；
- **STAR 审查**：项目经历四要素是否齐备、行动与结果是否量化（无量化输出 WARN）；
- **真实性审查**：技术栈/角色/数字自洽，不虚构公司、职级、具体机构；
- **冗余审查**：同类描述合并建议，降低 low 级内容占比。
审查意见以 WARN/建议形式展示，用户可一键触发对应板块重生成。

### 6.6 联网搜索（双模）
API 搜索为默认；BrowserSkill 深度取材为可选增强（BYO 账号、HITL、默认关闭、固定限频）；失败降级不阻塞，AI 按【待联网核实】协议标注（参考 MS-Agent v0.4.9）。

### 6.7 动态适配机制（核心痛点：填满页面、避免大面积空白）
**目标**：最终输出的简历**精确填满一页或两页**，避免任何页面下半部分大面积空白；当内容约为一页半时，自动调整布局消除第二页下半部分的空白。

**稠密度两层机制（v0.5 修订）**：
- **排版层稠密度——所有板块全局参与**：字号、行距、段落间距、区块间距、项目符号缩进等排版参数统一作用于全部板块，无例外；
- **内容层稠密度——内容生成弹性**：同一内容可"展开讲详细 / 精简说简短"（详略档），且**数量**（项目条数、每条要点数、自我评价句数）本身即为弹性的重要组成部分；由生成引擎按目标页数 + criticality + 剩余空间决定详略与数量，主要作用于自我评价/实习经历/项目经历等描述性板块（教育/技能/证书等由用户输入决定的内容量固定，不参与内容层弹性）。

**内容分区性质（v0.5 修订）**：
| 板块 | 分类 | 排版层参与 | 内容层弹性（详略+数量） | 弹性策略 |
|---|---|---|---|---|
| 个人信息（含照片） | 常驻·固定 | 参与 | 否 | 内容量固定，不可增减 |
| 教育背景 | 常驻·固定 | 参与 | 否 | 1~3 条由用户决定，条目内内容固定 |
| 自我评价 | 常驻·弹性 | 参与 | **是** | 句数 1~3 句、每句详略可调 |
| 实习经历 | 非常驻·弹性 | 参与 | **是** | 未填整块隐藏；要点数、每条详略可调 |
| 项目经历 | 常驻·弹性 | 参与 | **是** | 条数（硬性规则，见 §6.4）、每条要点数、详略可调 |
| 技能特长 | 常驻·固定 | 参与 | 否 | 内容分类/JD 拓展由生成引擎决定，量由用户+拓展决定 |
| 证书荣誉 | 非常驻·固定 | 参与 | 否 | 未填或用户选择时整块隐藏 |

**内容关键性分级（criticality，v0.5 新增）**：生成/美化时给每条内容（项目、实习要点、自我评价句子、荣誉条目）标记关键性等级，作为动态适配的裁剪依据——
- `critical`：与 JD 直接相关、核心量化成果（**绝不裁剪**）；
- `high`：重要职责/成果；
- `medium`：一般描述；
- `low`：辅助信息（次要荣誉、泛化描述）。
裁剪按 low → medium → high → critical 顺序执行；排版层调整不改变内容关键性。

**调整手段（模板以 `body[data-density]` 驱动排版层；内容层由生成引擎在内容侧约束阶段执行）**：
- 排版层（全部板块，全局统一）：
  - 字号：正文在**预设范围内**微调（一页 9.5~10.5pt、两页 10.5~11.5pt，以基线为中心 ±0.5pt）；
  - 行距与段落间距：区块间距 `--gap`、行距 `--lheight`、要点间距联动；
  - 项目符号缩进：列表左缩进微调（一页 10~18px、两页 12~20px）；
  - 三档：compact / normal / loose。
- 内容层（描述性板块，生成引擎控制）：
  - 详略档：详细 / 标准 / 精简（描述篇幅）；
  - 数量档：项目条数、每条要点数、自我评价句数；
  - 依据：目标页数 + criticality（critical 项必保）+ 剩余空间。

**适配机制（构建期，分三层）**：
1. **内容侧约束**（生成时）：**项目条数先按 §6.4 数量硬性约束定死**（一页 1~2 / 两页 1~3，随实习条数 0/1/2 → 3/2/1 条），再按目标页数 + criticality 决定其余详略与数量——一页版：每条 2~3 要点、自我评价 1~2 句、详略精简；两页版：每条 3~4 要点、自我评价 2~3 句、详略标准；生成内容"宁多勿少"，交由排版侧压缩。（描述性板块按目标页数可用高度做**高精度空间预算**：模型篇幅自估 + 实测校准，见 §6.1.1-4）
2. **排版侧微调**（渲染后测量）：渲染完成后测量内容高度，**以关键路径（critical path）为指导**——内容量最大的弹性板块为主导板块，优先调整其排版层密度——
   - **超页**（溢出目标页数）：逐级压缩——按 criticality 从低到高裁剪非常驻条目（low→medium）→ 主导板块内容层降档（详细→标准→精简，减少要点/句数）→ 合并项目要点 → 精简自我评价（保留 critical 句）→ 排版层全局密度档切换（loose→normal→compact）；
   - **不足**（末页填充度 <75%）：逐级扩充——追加自我评价句子（至 critical 句数上限）→ 主导板块内容层升档（精简→标准→详细，增加要点/技术栈详情）→ 排版层全局密度档切换（compact→normal→loose）；
   - **排版层全局密度档**：compact / normal / loose，作用于全部板块（含全局字号/要点间距/缩进联动）——一页版 gap 6px / 9px / 14px、行距 1.28 / 1.35 / 1.45；两页版 gap 9px / 14px / 20px、行距 1.40 / 1.50 / 1.62。
3. **显隐侧整合**：非常驻板块（实习经历、证书荣誉）未填写或用户选择时自动隐藏；隐藏后整体布局自动收缩重排，保证无空洞。

**页数判定**：目标页数 = 用户勾选的分页选项（一页 / 两页），**由用户直接决定，不通过内容测量推断页数**；动态适配只负责把内容收敛到用户所选目标页数，不改变页数结果。

**收敛（参数定稿）**：`渲染 → 测量 → 调整 → 重渲染`，**最多 3 轮**收敛到目标页数；填充判定——末页填充度 **≥85% 视为填满**、**75%~85% 可接受**、**<75% 触发扩充**、**>100% 触发压缩**（两页版以第 2 页为准）；仍无法收敛时优先保证不溢出（宁可紧凑，不可溢出）。

### 6.8 项目经历生成规则（v0.4 定稿）

**生成流水线**：JD 分析（§3.1.6 主题一致性规则）→ 项目类型匹配（下方映射表）→ 联网取证（真实生产环境的实施流程/技术栈/成果指标，失败降级不阻塞）→ STAR 自然段落生成（无 S/T/A/R 标识）→ 量化数值直接生成（合理数值 + 行业精度规则，如性能提升 12.5%、延迟降至 120ms、支持 800QPS；见 §6.10 规则层）→ **criticality 标注**（每条要点按与 JD 相关度与量化强度标记 critical/high/medium/low）→ 批判性审阅（§6.5）。

**规则文件**：`rules/projects/*.json`，独立于代码、版本化可迭代（规则引擎见 §3.3-8）。

**Prompt 分层结构（系统提示词组装顺序）**：
1. **系统身份层**：专业简历撰写助手，遵循 ATS 规范、STAR 融入自然段落（不显示 S/T/A/R 标识）、合规边界（实习经历不创造、项目创造带合理量化数值）；
2. **规则层**：**数值直接生成规则**（数值合理、贴合行业口径与上下文；精度按指标类型——百分比取整数或 1 位小数、延迟/时间按量级取整（ms/s）、吞吐/人数取整（QPS/并发/人）；禁止极端值如 1000% 提升、0 成本）、技能必填/拓展、身份差异化（实习生/全职）、简历不展示目标岗位字段、字数/要点数范围（按分页选项）、**criticality 标注规则**（与 JD 相关度 + 量化强度 → critical/high/medium/low）；
3. **行业上下文层**：按职业方向匹配并注入对应行业模板库条目（keywords/skills/metric_style/tone/notes/project_types）；
4. **用户数据层**：基本信息、教育、实习、项目、技能、荣誉、照片；
5. **JD 分析层**：主题一致性校验结果、核心技能词、岗位侧重（§3.1.6 规则产出）；
6. **联网资料层（可选）**：真实行业案例与成果指标（§6.6 双模搜索产出）；
7. **批判性自审层**：生成后以 HR 视角审查关键性/匹配度/STAR/真实性/冗余（§6.5）；
8. **输出约束层**：按板块结构化输出、内容量匹配分页选项（项目条数按 §6.4 数量硬性约束：一页 1~2 / 两页 1~3，随实习条数 0/1/2 → 3/2/1 条）、每条内容携带 `criticality` 字段、JSON 结构约定。

**落地节奏**：开发阶段先建 5 个核心行业条目（互联网/金融/快消/制造/游戏），其余按需扩展；模板库文件独立于代码、版本化可迭代。

## 7. 非功能需求

- **安全与隐私**：数据仅存本机/用户可控；API Key 脱敏存储（沿用 MS-Agent 的 maskKey 思路）；不上传无需联网的数据；BrowserSkill 深度取材模式下用户账号数据不出本机、抓取内容不落库不存储不导出。
- **部署形态（v0.6 定稿）**：**本地单用户运行**——用户从 GitHub 下载后在个人机器本地启动（延续 MS-Agent 模式）；无云服务、无独立数据库服务、无鉴权体系；**无需并发控制与多用户支持**；生成任务单任务串行执行（超时/取消由单用户操作触发）。
- **开发 SOP：质量优先，先完整后压缩（v0.6 定稿）**：开发期强制先交付**功能完整、代码质量与体验达标**的标准版本（normal 密度基线、内容按完整详略生成）；该版本定稿后，再叠加稠密度优化/压缩适配；**任何密度调整不得牺牲内容完整性与质量**——压缩严格按 §6.4/§6.7 顺序（排版层优先 → 内容层次之 → 裁剪兜底，critical 项绝不裁剪）。
- **性能**：生成任务异步化，支持进度反馈与取消；生成时长控制在可接受范围（动态适配收敛轮数受限，避免反复重渲染）。
- **可扩展**：规则引擎独立于代码可迭代；经历类型可扩展；秋招版字段预留。
- **限频安全**：BrowserSkill 深度取材采用**固定限频策略**（用户不可修改），保障系统安全与账号安全；界面明示"速度降低但准确率与信息质量提升"的预期。

## 9. 文档体系规划（借鉴 MS-Agent 的 MSA进化路径.md）

MS-Agent 的 `MSA进化路径.md` 是其权威技术文档（风险矩阵 + 版本记录），简历生成助手 在开发阶段应同步建立同类文档体系：

1. **简历生成助手 风险扫描矩阵**（对标 MSA 的 9 环节风险表）：覆盖环境准备 / 配置 / 表单输入 / 照片上传 / 生成流程 / 深度取材（BrowserSkill）/ 结果导出 / GitHub 上传等环节；每条风险记录 **根因 → 预防 → 排查流程**；另设**风险等级矩阵**（致命/高/中，重点盯防 Key 泄露、个人数据上传等）。
2. **版本变更记录**（对标 MSA 的版本记录规范）：按时间倒序；每条变更含 **背景 → 变更项 → 涉及文件 → 说明 → 验证方式**；落地后人工整理归档。
3. **设计建议沉淀**：每个版本把加固项列入待办清单（如：默认 .gitignore 入库、config.example.json 随仓库发布、双 provider 冗余、审核问题自动重生成闭环）。
4. **文档同步纪律（SOP-04 思路）**：结构/机制变更后同步 README 与规范文档，变更留痕。
5. **合规留痕**：完全创造内容、BrowserSkill 深度取材等高风险决策，在文档中记录决策背景与边界，避免重复评估（对标 MSA 的「明确不落地」决策记录）。
