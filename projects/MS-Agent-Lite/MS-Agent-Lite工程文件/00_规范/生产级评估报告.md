### 2.2 风险面说明

- **XSS 纵深**：虽然 build.js 的注入链已转义，但 `annotateText` 术语高亮在 `escapeHtml` 之后执行——需回归验证"术语含 HTML 元字符"时不会破坏转义（建议加一条 verify 断言）。
- **供应链**：仅 pdfjs-dist / mammoth / @napi-rs/canvas 三个依赖（@napi-rs/canvas 实际未使用，可移除以缩小攻击面与安装体积）；建议 `npm audit` 定期检查。
- **本地服务无鉴权**：127.0.0.1 绑定后本机其他进程仍可访问（浏览器扩展/恶意软件场景），生产级可加一共享 token 头；单机自用优先级低。

## 三、性能评估

| # | 瓶颈 | 影响 | 等级 | 优化方案 |
|---|------|------|:---:|---------|
| P1 | **8 文件串行生成**（每次 1 个 LLM 请求，含完整上下文） | 免费小模型全流程 3~10 分钟；上下文重复消耗 token（8 次 × 全量） | ❗ | 限流并行（如 2~3 并发，注意 API QPS 与错误率）；上下文按文件裁剪（每文件只带相关部分） |
| P2 | **上下文无 token 上限**（JD+卡片+简历+全部 urls 全量注入每文件） | 长 JD/多网址时小模型上下文溢出或截断，质量下降 | ❗ | urls 每条截断 8000 字符 + 总量上限；JD 超长摘要 |
| P3 | **build/verify 用 `execFileSync` 同步阻塞事件循环** | 渲染/校验期间 SSE 与 API 短暂卡顿（build 秒级，影响小） | ⚠️ | 改 `execFile`（async）或 worker 线程；当前可接受 |
| P4 | **tasks Map 全量驻留**（事件/结果/客户端） | 长期运行内存线性增长 | ⚠️ | 终态任务 TTL（30 分钟）+ 客户端断开清理 |
| P5 | fetch_jd 15s 超时 + 重试 1 次（30s 上限） | 慢站/失败站体验 | ✅ 已权衡 | 保持；仅提示降级 |
| P6 | 取消不中断进行中的 LLM 请求（`callText` 不接收 signal） | 取消后仍空耗请求额度与 60s 等待 | ❗ | `callText` 增加 signal 参数，abort 时 `req.destroy()` |

## 五、架构评估

### 5.1 优点（值得保持）

1. **纯 Node 零框架 + 零构建**：分发/维护成本极低，无框架锁定。
2. **相对路径全部基于 `__dirname`**：任意目录解压可跑（GitHub 分发场景成立）。
3. **单实现双入口**：`buildSharedCtx`/`FILES` 被 server 与 CLI 共用，避免双份逻辑漂移。
4. **尽力而为的错误哲学**：单文件失败不阻断、参考网址逐条尽力、审核失败仅告警——符合"用户能拿到最好结果"的产品预期。
5. **SSE 事件全量落盘 + 重放**：断线恢复能力在零依赖前提下做得扎实。

### 5.2 架构缺陷

| # | 缺陷 | 影响 | 建议 |
|---|------|------|------|
| A1 | **vision 能力"纸面化"**：vision_analyze.js 独立存在但管线从未调用；UI 引导用户配视觉模型/选三分类，对结果零影响 | 承诺与实现不符（用户信任风险）；扫描件简历静默产出空文本 | 二选一：真正集成（简历图片→视觉提取进上下文）或 UI 明示"当前仅文本能力"；并加扫描件检测（解析文本 <200 字符提示） |
| A2 | **gen_material.js usage 与实现不一致**（`--jd "文本"` vs `--jd=`） | CLI 按 usage 输入直接报错 | 统一用法或双写法兼容 |
| A3 | **生成物硬编码岗位**：build.js 输出 `<title>` 与顶栏写死"系统架构组/系统研发实习生" | 生成任何公司材料都显示旧岗位（更名遗漏） | 参数化为 `${comp} · 面试流程` |
| A4 | **单进程无持久化**（tasks 内存态） | 重启丢进度 | 任务 JSON 落盘 + 启动扫描恢复 |
| A5 | **无自动化测试**：仅 --dryrun 查配置 | 改动回归无保护（本次多轮修复全靠人工/子代理验证） | 加最小冒烟：固定 JD → 生成 1 文件 → build → verify 断言 |

## 七、结论

系统**核心链路已达可用级**（分发-配置-生成-重试闭环已打通，本轮补齐了 retry 数据一致性、首次运行崩溃、doc 兼容、输入预检等真实断点）。剩余问题集中为：
- **3 项"纸面承诺"**（A1 vision、A2 CLI usage、A3 硬编码岗位）——建议第一批全部清掉；
- **4 项可靠性**（P6 取消、P4 内存、D3/D4 目录语义与互斥）——第一批；
- **1 项性能重构**（P1 并行）——第二批随上下文裁剪一起做，收益最大。

按第一批执行后，系统可视为"单机生产级"基线；第二批为体验与成本优化；第三批按产品路线演进。
