# 总实施计划 v1（定稿）

> 决策记录：2026-08-14 用户拍板——接受整体大改；对四个子项目**选择性 Agent 化升级**；四个子项目**并入一个新的 LangGraph 项目**
> 依据：`改造设计/` 下 5 份设计文档 + 第一性原理论证（Agent = LLM+反馈回路+终止条件）

## 一、升级矩阵（选择性 Agent 化的精确判定）

| 子项目 | 升级内容 | 是否 Agent 化 | 理由 |
|---|---|---|---|
| **JS-Agent** | ① 混合判定（硬约束规则+LLM 软性判定，0.6/0.4 否决制）② 搜索回路（LLM 决策五行动+代码刹车四闸门）| ✅ **真 Agent 化**（LLM 决策回路）| 搜索策略/判定质量是决策问题，回路有真实收益 |
| **JL-Agent** | reviewing 审核阶段（混合审核+带意见重写+edited 保护）| ❌ 只加确定性回路 | 简历内容不允许 LLM 自主发挥（防编造）|
| **MS-Agent-Lite** | 文件级审核回路（白名单 4 文件+规则优先+带意见回炉）| ❌ 只加确定性回路 | 同上 |
| **interview-tracker** | 不改造 | ❌ 纯工具 | 无决策语义 |

**原则**：Agent 化只给"决策问题"（JS-Agent）；质量闸门用确定性回路；工具保持工具。

## 四、与 Dify 的关系（按用户工作流）

```
Dify 画布（脚本层可视化）⇄ DSL 导出 ⇄ 工程师升级
        ↕ HTTP
LangGraph 大脑（Agent 层）—— tools/ 封装 —— 四子项目
```

- 大脑节点调用地址：`tools/*.py` 中一个 URL 常量切换（原生 API ↔ Dify 工作流 API）
- Dify 工作流是"脚本层的可视化实现"，不是 LangChain
