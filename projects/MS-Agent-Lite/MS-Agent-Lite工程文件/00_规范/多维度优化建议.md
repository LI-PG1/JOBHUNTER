# MS-Agent 多维度优化建议

> 版本：v0.3.0（2026-08-05）
> 本文档从**降本增效**之外的多个维度给出优化建议，区分「✅ 已实施（v0.3.0）」与「🔜 建议（后续迭代）」，供排期参考。
> 相关文档：`00_规范/SOP.md`（SOP 核心架构原则）、`00_规范/生产级评估报告.md`（历史问题清单）。

## 0. 降本增效总览（需求 2：HTML 生成提速）

### ✅ 已实施（v0.3.0）

| 优化 | 收益 | 落地 |
|---|---|---|
| **模板分层**：54KB 静态模板从 build.js 内联 → `templates/skeleton.html` | 消除每次全量解析 54KB 模板字面量的开销；模板一次维护 | [build.js](file:///d:/TRAE/WORKSPACE/MS-Agent/20_执行/build.js) + [skeleton.html](file:///d:/TRAE/WORKSPACE/MS-Agent/20_执行/templates/skeleton.html) |
| **增量构建**：sha256(源 md) 缓存比对 | 源内容未变 → 直接跳过渲染（0 计算开销） | build.js「增量构建」块 + `.build-cache.json` |
| **组件化提示**：intro/star 结构框架注入 prompt | 减少 LLM 结构漂移与重复设计，输出一致性↑ | [components/](file:///d:/TRAE/WORKSPACE/MS-Agent/20_执行/components/index.js) |
| **限流并行**：8 文件串行 → 最多 3 并发 | 生成阶段总耗时 ≈ 串行的 1/3（实测并发峰值 3） | pipeline.js `mapLimit` + `MS_AGENT_CONCURRENCY` |
| **术语表共享**：GLOSSARY/EXTRA → `glossary.js` | 一次维护所有公司复用 | [glossary.js](file:///d:/TRAE/WORKSPACE/MS-Agent/20_执行/glossary.js) |

**字节级回归验证**：重构后产物与原版逐字节一致（`IDENTICAL`），verify `RESULT: PASS`。

### 🔜 建议（进一步精简 HTML 生成）

1. **并行 build 子任务**：build 内 md 读取/拆分/重组目前同步串行，量级小（<50ms），可暂缓；若未来单文件超大可并行化。
2. **HTML 数据分片**：`FILES_JSON`（7 个 md 全文）随内容增长，可改为「首次加载骨架 + 按阶段懒加载对应 md」，降低首屏解析与内存占用。
3. **模板预编译**：将 skeleton 的渲染 JS（折叠/高亮/术语 tooltip）拆为独立 `.js` 静态文件引用，骨架只留结构与 CSS，进一步缩小每次注入体积。
4. **SSR 缓存**：以「公司名 + 简历版本 + 内容 hash」为 key 在内存/磁盘缓存已渲染 HTML，前端直接命中（当前已接近此效果）。

## 1. 系统稳定性（需求 4）

### ✅ 已实施
- **增量缓存**：源 md 未变跳过渲染，减少不稳定源（磁盘/进程）暴露面。
- **组件兜底**：`01_自我介绍` LLM 失败时写本地占位，build 不因缺文件中断（SOP-05）。
- **子进程超时**：build/verify 120s 超时强制 kill，防挂死占锁（历史 P3 修复）。

### 🔜 建议
- **任务队列持久化**：任务状态落盘（当前仅上下文快照），重启后恢复未完成任务。
- **provider 健康检查**：启动时 ping 各 provider，标记不可用者，避免每次首请求失败重试。
- **进程守护**：server.js 以 PM2/Windows 服务托管，崩溃自动拉起。

## 2. 可扩展性

### ✅ 已实施
- **组件注册表**：新增内容组件 = 加模块进 `REGISTRY`，pipeline/verify 自动生效（零侵入扩展）。
- **并发可调**：`MS_AGENT_CONCURRENCY` 环境变量控制生成并发（1 串行 ~ 8 上限）。
- **多 provider 链**：文本/视觉按 cap 自动选择 + 失败切换（既有架构）。

### 🔜 建议
- **多 Agent 分工**（agent化设计文档 M4）：搜索 Agent / 面经回填 / Critic 自修复独立进程，横向扩展。
- **模板市场**：skeleton.html 支持多主题（深色/极简），按公司/岗位参数化选择。
- **跨岗位记忆**：术语表/组件按领域（Agent/RAG/部署）分组，岗位切换只换子集。

---

## 3. 错误处理

### ✅ 已实施
- **分层兜底**：组件 fallback（内容级）→ SKIPPED 告警（章节级）→ 单文件失败继续（文件级）→ 全失败终止。
- **可见告警**：被跳过章节注入 HTML 顶部 `build-warn` 横幅（新手不看控制台也能发现）。
- **全链路取消**：AbortSignal 透传，LLM 请求即时中断，不空耗额度。

### 🔜 建议
- **错误分类与统计**：按 provider/文件类型归类失败原因，沉淀"失败模式库"（如 max_tokens 超限→降级）。
- **自动重试策略**：瞬时错误（网络抖动）自动重试 1 次（fetch_jd 已有，生成阶段可加指数退避）。
- **告警通道**：build-warn 之外支持邮件/企业微信推送关键失败。

## 4. 资源利用

### ✅ 已实施
- **限流并行**：3 并发平衡吞吐与 API 限流，避免 8 连发打爆 provider。
- **增量跳过**：内容未变零渲染，省 CPU 与磁盘 IO。
- **响应体上限**：LLM 响应 10MB、网页 2MB 上限，防内存被拖垮。

### 🔜 建议
- **上下文瘦身**：当前每文件复用完整上下文（JD 20k + 卡 + 画像），可按文件裁剪（如 00_公司背景 不需要数字口径明细），token 成本再降。
- **请求合并**：相邻小文件合并为一次多段生成（牺牲并行换 token），需 A/B 评估。
- **流式输出**：SSE 逐 token 展示生成进度，首字节更快、取消更及时。

## 5. 用户体验

### ✅ 已实施
- **SOP-CHECK 可视化**：verify 输出结构化检查点，用户可读状态而非裸 PASS/FAIL。
- **结果路径提示**：done 事件携带产物完整路径，弹窗指引小白用户。
- **兜底占位可恢复**：fallback 文件在结果页可"重试生成"覆盖。

### 🔜 建议
- **生成进度粒度**：并发生成下按文件显示"进行中/成功/失败"，前端已有基础，可加预估剩余时间。
- **差异预览**：重试文件前后 diff 展示，用户确认覆盖。
- **暗色模式**（agent化设计文档 M2）：骨架 CSS 变量化，一键切换。

---

## 6. 输出准确性

### ✅ 已实施
- **组件结构校验**：verify 检查 intro/star 框架标记（SOP-CHECK），结构不达标即 WARN。
- **章节白名单**：REQUIRED_SECTIONS 核对 build 注入章节，缺标题即 FAIL（历史 P1-7 修复）。
- **数字口径红线**：参与边界卡唯一权威 + runCheck LLM 审核（PASS/WARN）。

### 🔜 建议
- **数字交叉校验**：脚本扫描 md 中数字与参与边界卡逐项比对（比 LLM 审核更可靠）。
- **术语一致性**：同一概念（如"30+ 模型"）全文统一写法，脚本检测冲突。
- **多轮自检**（agent化设计文档 M3）：Critic Agent 对输出二次审查后回填修正。

---

## 7. 可维护性

### ✅ 已实施
- **模板/组件/术语表分离**：改一处全局生效，改样式不动 build 逻辑、改术语不动模板。
- **SOP 文档化**：`00_规范/SOP.md` 定义 SOP-01~06 + 代码位置对照（SOP-04 文档同步）。
- **模块化**：pipeline / llm_gateway / verify / build 职责清晰，互不内联。

### 🔜 建议
- **自动化测试**（历史 A5）：为 build 装配、verify 检查、mapLimit 并发补 Node 单测，接入 CI。
- **类型化**：核心数据结构（files/phases/组件）抽 schema，跨脚本共享，防字段漂移。
- **变更日志**：README 维护 CHANGELOG，大版本变更自动触发 SOP-04 检查。

## 8. 优先级建议（短期 → 中期）

| 优先级 | 事项 | 维度 |
|---|---|---|
| P0 | 上下文按文件瘦身（token 成本大头） | 资源利用 |
| P0 | 数字交叉校验脚本（防口径错误） | 输出准确性 |
| P1 | 自动化测试（build/verify/并发） | 可维护性 |
| P1 | 流式输出 + 进度预估 | 用户体验 |
| P2 | 任务队列持久化 / provider 健康检查 | 稳定性 |
| P2 | 多 Agent 分工（M4） | 可扩展性 |
