## §1 产品定位

**一句话**：应届生求职助手——从"我做过什么（详细）"到"一份能打的简历 + 能投的岗位 + 面试准备 + 投递跟踪"。

| 项 | 定义 |
|---|---|
| 核心用户 | 应届生（硕/本），第一次求职 |
| 核心链路 | **简历生成 → 岗位匹配 → 面试准备 → 面试跟踪**（四大板块，顶部常驻栏切换） |
| 输入原则 | 允许用户尽可能详细地描述教育/项目/实习（越详细，LLM 优化与匹配越准） |
| 输出原则 | 简历 A4 视窗可导出 PDF；工程字段全部折叠；结论带下一步 |

## §2 信息架构（v0.2）

```
顶部常驻栏：品牌 | 简历生成 | 岗位匹配 | 面试准备 | 面试跟踪 | ⚙控制台 | 模式pill
每个板块：
  左栏常驻流程栏（rail）：子步骤引导 + 快速跳转（对齐 JS-Agent/JL-Agent 前端模式）
  主内容区：当前子步骤卡片
```

### 板块 A：简历生成
- 左栏：① 填写画像 → ② 生成并预览 → ③ 导出
- 画像（分块折叠，对齐 JL-Agent 表单风格）：
  - 基本信息：姓名 / 求职方向 / 期望城市
  - 教育经历（应届生必填）：学校 / 专业 / 学历 / 毕业年份（可多条）
  - 项目经历（详细）：名称 / 角色 / 时间 / 技术栈 / 详细描述 textarea（可多条）
  - 实习经历（**独立区块**）：公司 / 岗位 / 时间 / 详细职责 textarea（可多条）
  - 技能（标签）
  - 目标岗位：标题 / JD（可多条）
- 生成：按钮 → 简历 A4 视窗（白纸样式，完整展示：教育/项目/实习/技能/摘要）
- 导出：`导出 PDF`（浏览器打印，零依赖）

### 板块 B：岗位匹配
- 左栏：① 匹配画像 → ② 岗位清单 → ③ 收藏与投递
- 岗位卡片：匹配度环 + 岗位/公司/城市/薪资 + 技能线 + 详情展开（为什么匹配/还缺什么）+ 收藏
- 收藏清单 = 投递清单雏形（localStorage）

### 板块 C：面试准备
- 左栏：① 面试材料 → ② 面试复盘
- 材料文件列表（N9 产物）+ 复盘报告（N10B msr_report）

### 板块 D：面试跟踪
- 投递记录表格（公司/岗位/状态/时间），状态标签（已投/面试/通过/结束），对齐 interview-tracker 风格
- MVP：localStorage 持久化

### 控制台（modal，对齐 JS-Agent）
- 模型与 Key：厂商 / 模型 / API Key（保存 / 测试）→ 后端 /api/console
- 插件管理：列出四子项目能力（JL 简历 / JS 搜索 / MS 材料 / tracker 跟踪）+ 启停
- 运行模式：mock / real 显示与切换

## §3 文案规范（工程 → 用户语言）

| 工程字段/事件 | 用户文案 |
|---|---|
| `gate_verdict: pass` | 「你的简历和岗位方向很匹配，可以直接投递」 |
| `accept_with_issues` | 「整体达标，按下方建议再优化一下会更好」 |
| `fail` | 「匹配度还没到位，先按建议优化简历再投」 |
| 轮次上限降级 | 「已为你自动优化多轮，以下是最佳结果」 |
| 无匹配收录 | 「技能覆盖不足，建议回到简历板块补充项目描述」 |
| 分数 | 匹配度环 + 颜色（≥80 很匹配 / 60-79 可考虑 / <60 需提升） |

原则：不出现代码字段名；结论以"你"为主语 + 下一步。

## §4 与后端的关系

## §6 v0.3 增量（2026-08-16，用户 5 点新反馈）

> 反馈 → 决策 → 落地全链路。核心思路：**简历版本只分析一次，各板块共用；面试追踪 100% 复现子项目界面与逻辑规则。**

| # | 用户反馈 | 决策（AskUserQuestion 确认） | 落地 |
|---|---------|------------------------------|------|
| 1 | 岗位清单应允许导出 | **CSV（Excel 直接打开，推荐）**，带 BOM 防乱码 | `exportJobsCsv` 纯前端 Blob 下载，匹配成功后按钮显隐 |
| 2 | 面试准备允许选版本 + 输入 JD + 补充面经链接 | 版本下拉共用；JD / 面经并入 `target_jobs[0].jd` 供材料节点消费 | `inpIntVer` / `inpIntJd` / `inpIntExtra` → `/api/run` payload |
| 3 | 匹配画像允许选择简历版本 / 手动上传 | 上传集合到「简历生成」板块单独列版本，系统自动按 **A-Z** 分配 | localStorage `jobhunter_resumes`，各板块下拉 `renderVersionOptions` 共用 |
| 4 | 匹配画像是否提供方向选项 | **不是固定预设下拉，而是分析后推荐 top5**（点击选用） | `DIR_RULES` 11 方向关键词打分 → chips 渲染，点击写回画像首行 |
| 5 | 面试追踪与子项目差距过大 | **完整复现**（界面 + 逻辑规则） | trk* 模块：dashboard / 智能识别 / 工具栏 / 分组 / 状态机 / 提醒 |

### 6.1 简历版本管理（A-Z 自动编号）

- 存储：localStorage `jobhunter_resumes`（`{id, letter, name, source, text, updatedAt}`）+ `jobhunter_active_resume`（当前激活版本）
- 入口：**简历生成板块第 4 张卡「简历版本」**——上传 txt/md（`FileReader` utf-8）或粘贴文本「保存为版本」
- 生成简历时自动保存「表单版」（同名去重更新），`letter` 取第一个未用字母 A→Z
- 共享：匹配板块 `inpResumeVer`、面试准备 `inpIntVer` 下拉复用同一份版本；选择后自动带出到画像文本框并触发方向推荐
- 旧 `jobhunter_tracks` 扁平记录一次性迁移为 companies/jobs 结构

### 6.2 匹配方向推荐 top5（非固定下拉）

- `DIR_RULES`：11 个方向（大模型应用 / ML算法 / 后端 / 数据科学 / 前端 / 测试 / 云计算 / CV / NLP / 推荐 / 风控）各含关键词表
- `recommendDirections(text)`：对画像文本做关键词命中打分，排序取 **前 5**，渲染为 `.chip`（方向名 + 分值）
- 点击 chip：写回画像文本框首行 `求职方向：xxx`（幂等替换），chip 高亮

### 6.3 岗位清单 CSV 导出

- `exportJobsCsv(jobs)`：`\uFEFF` BOM + `"值"` 转义 + `\r\n` 换行 → Blob + `<a download>`；表头：岗位/公司/城市/薪资/匹配度/来源/技能/要求/链接
- 匹配成功后 `window._lastJobs` 缓存 + `#btnExportCsv` 显隐；点击即下载 `jobhunter-jobs-YYYY-MM-DD.csv`

### 6.4 面试准备增强

- 选版本（`inpIntVer`）+ 意向岗位 JD（`inpIntJd`）+ 补充信息/面经链接（`inpIntExtra`）
- Payload：`profile.text` = 版本文本（透传）；`target_jobs` 追加 `{title:"意向岗位", jd: JD + "\n\n补充信息（面经 / 备注）：" + 面经}`
- 生成成功后状态从「生成中…」置为「✓ 已生成」

### 6.5 面试追踪完整复现（interview-tracker 子项目）

后端新增（`web/routers/ai.py`，注册于 `/api`）：

- `POST /api/ai/test`：探测 `LLM_API_KEY` 是否配置（`.env`），返回 `{ok}` → 前端决定智能识别区是否置灰
- `POST /api/ai/parse`：mock = 正则规则抽取（公司/岗位/城市/日期/datetime/不确定项 `uncertain`）；real = OpenAI 兼容 LLM 结构化 JSON（剥除 ```json 围栏）

前端 trk* 模块（数据存 localStorage `jobhunter_tracker_data`，companies/jobs 分离）：

- **今日要点 dashboard**：置顶栏（Offer 待确认 / 未来面试自动置顶 / 手动置顶，`inPinnedBar`）+ 待办提醒条（未来 7 天面试/笔试/待办 + 14 天 Offer 窗口，`trkRenderReminders`，同投递同天去重，置顶与提醒互斥）+ 实时时钟
- **智能识别**：无 Key → `.quick-parse.off` 置灰禁用 + 提示「点 ⚙ API 配置」；有 Key → 粘贴文本 → `/api/ai/parse` → 结果进入**确认表单**（可修改，`uncertain` 高亮提示）→ 保存；「⚙ API」按钮复用控制台 modal
- **流程环节模型**：`stages = {resume, written, interviews[], hr}`，每轮 `{date, state: pass|wait|todo|fail|skip}`，笔试行带 DDL；`stageList` 骨架 + 动态面试轮（一/二/三…面，可增删）
- **状态机 `normalizeStages`**：fail 清空后续环节；pass 置下一环节 todo；有面试信息 → 隐含 resume/written 通过；终态 fail/giveup 自动断链
- **分组 `jobGroup`**：0=已投待进展 / 1=进行中 / 2=已挂放弃 / 3=Offer（结果 offer 最高优先）；`allStagesPassed` / `interviewSettled` / `hasFutureInterview` 判定
- **排序分层 `sortGroup`**：未来面试(0) → 笔试 DDL 48h(1) → Offer 待确认(1.5) → 手动置顶(2) → 常规(3) → 终态(4)；组内 `priorityScore`（深度饱和 0.6 + 7 天指数衰减新鲜度 0.4 + 待办 +0.15 + 有转正 +0.1）
- **横版卡片**：星标（☆/★，off/on/auto 三态，auto 为面试自动置顶）+ 公司/岗位/标签（秋招/有转正/日常/未知）+ 流程 chip 流 + meta（投递日期/城市/面试/笔试 DDL/Offer 截止/待办/可展开备注）+ 更新按钮；岗位名未填显示「＋ 补全岗位名」
- **筛选**：搜索框（公司/岗位）+ 状态下拉 + 城市下拉（自动收集）+ 工作类型 + 分类 Tab（全部/实习/秋招/Offer）
- **弹窗**：新增（公司/城市下拉优先、识别确认模式工作类型必选）/ 更新（动态环节 + 最终结果 + 「🏆 标记为 Offer」一键全通过）；校验必填 + 同名岗位防重复；保存后自动 `trkSaveData()` 落 localStorage + 全量重排 + toast
