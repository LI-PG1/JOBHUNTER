# 大脑前端设计（统一业务前端 · FastAPI 薄封装 · 融合 JS 匹配）

> 状态：**v0.1 已实施**（2026-08-15 落地，M1-M6 全部完成并端到端验证）
> 定位：JobHunter 大脑骨架（LangGraph job_hunter v0.4）的**统一业务前端**，
> 用户不再依赖 LangGraph Studio 调试界面，而是通过 Web 页面输入画像、一键跑全流程、查看结果。
> 配套：`4_大改造架构设计-v2.0.md`（骨架架构）｜`端到端测试报告-20260815.md`（耗时基线）

---

## §1 目标与形态

| 项 | 决策 |
|---|---|
| 形态 | 统一业务前端（求职工作台），单页多板块 |
| 后端 | 自建 FastAPI 薄封装（封装 LangGraph 图调用 + 转发 JS 匹配） |
| 技术栈 | 原生 HTML/CSS/JS 单页（无构建链，与四子项目前端风格一致） |
| JS 融合 | 前端「岗位搜索匹配」板块对接 JS-Agent 匹配能力（岗位清单 + 匹配度），与大脑 N4 结果同屏展示 |
| 运行模式 | 默认 mock 全流程可跑；real 需配置 LLM_API_KEY 与四项目服务 |

## §2 架构

```
浏览器（原生 JS 单页）
   │  fetch /api/*
   ▼
FastAPI 薄封装  D:\Drivers\JobMaker\web\
   ├── POST /api/run          → 进程内 build_graph().compile().invoke()（同步）
   ├── POST /api/match        → 转发 JS-Agent /api/match（异步 job，轮询）
   ├── GET  /api/match/{id}   → 转发 JS-Agent 匹配状态
   └── GET  /api/health       → 服务与依赖探测
   ▼
大脑骨架（D:\Drivers\JobMaker\graph\）  ←── 进程内组件（resume_agent / match_agent）
   节点 N1→N10：画像解析→简历→匹配→判定→差距→改进→材料→跟踪→复盘→报告
```

对接选择（骨架 `clients/api_client.py` 四项目 HTTP 客户端为回退通道）：
- 大脑全流程：**进程内**组件调用（Q9 已确认），FastAPI 直接 import `graph.build.build_graph`
- 独立匹配板块：**转发 JS-Agent** `POST http://127.0.0.1:8001/api/match`（融合 JS 的岗位清单能力）

## §3 后端 API 契约（FastAPI 薄封装）

| 接口 | 方法 | 入参 | 返回 |
|---|---|---|---|
| `/api/run` | POST | `{profile, target_jobs, user_goal}` | 全流程最终 state：resume / match_results / gate_verdict / resume_feedback / interview_materials / report / n7_stats / errors |
| `/api/match` | POST | `{profile, resume?}` | `{job_id, status: "running"}`（转发 JS-Agent） |
| `/api/match/{job_id}` | GET | — | `{status, jobs: [...岗位清单], done}`（轮询） |
| `/api/n7-stats` | GET | — | `n7_stats` 快照（诊断面板用） |
| `/api/health` | GET | — | `{ok, mode, deps: {langgraph, js_agent}}` |

> 同步设计：/api/run 为同步阻塞调用（mock 全流程 ~130ms，real 秒级可接受）；
> 若 real 模式耗时过长，后续升级为 `POST /api/run`（异步 job）→ `GET /api/run/{id}` 轮询 + SSE 节点进度。

## §4 前端页面结构（单页多板块）

```
┌───────────────────────────────────────────────┐
│  JobHunter 求职工作台  [模式: mock/real] [运行] │  ← 顶栏
├───────────────────────────────────────────────┤
│ Tab1 画像输入    Tab2 一键运行   Tab3 岗位匹配  │  ← 板块切换
├───────────────────────────────────────────────┤
│ Tab1 画像输入                                  │
│   技能 tags / 经历列表 / 偏好(类型/城市/方向)    │
│   目标岗位表（标题 + JD 文本，可增删）           │
│ Tab2 一键运行（调 /api/run）                    │
│   流程结果卡：简历预览(技能/项目/摘要)           │
│              匹配清单(match_results 表格)       │
│              质量判定徽章(pass/fail/降级)       │
│              差距建议列表(resume_feedback)      │
│              面试材料(interview_materials)      │
│              总报告 markdown 渲染               │
│ Tab3 岗位匹配（融合 JS-Agent）                  │
│   开始匹配 → 岗位清单表格（公司/城市/薪资/匹配度 │
│   /技能线/行业/学历/经验/状态/来源）             │
│   与 Tab2 的 match_results 双通道对比           │
└───────────────────────────────────────────────┘
```

关键交互：
- 顶栏「运行」= Tab1 表单 → 直接调 `/api/run` → 自动切到 Tab2 展示
- 每板块失败均展示 errors 明细（N7 日志摘要可选展示，诊断面板复用 `端到端测试报告` 思路）
- 状态徽章：pass=绿 / accept_with_issues=黄 / fail=红

## §5 JS 融合方案

| 层面 | 融合方式 |
|---|---|
| 能力 | 前端新增「岗位匹配」板块，复用 JS-Agent 岗位清单（公司/城市/薪资/匹配度/技能线）与投递状态展示 |
| 后端 | FastAPI 转发 JS-Agent 异步 match API（POST /api/match + 轮询），骨架 `clients.api_client.call_js_match` 同步补全 real 实现作为回退 |
| 数据 | Tab2 大脑匹配（match_agent 进程内结果）与 Tab3 JS-Agent 清单并列展示，供用户对比 |

> 说明：骨架 N4 已进程内集成 match_agent（JS-Agent 的 LangChain 化产物），
> 因此「融合 JS」= 前端获得独立岗位搜索/匹配入口 + 大脑全流程内嵌的匹配结果，两者并存。

## §6 目录与启动

```
D:\Drivers\JobMaker\
├── web\
│   ├── app.py            # FastAPI 入口（CORS + 静态页挂载 + 路由）
```
