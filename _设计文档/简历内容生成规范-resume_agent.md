## 二、内容生成标准（适配条款）

### 2.1 STAR 四要素与 S→T→R 逻辑链（迁移约束 4/5/6）

- **结构约定**：`ProjectItem` 平铺列表前 4 条语义固定为
  - **S**（背景基线）：项目背景 + 一条基线数字（现状/痛点量化，如"手工排期数天"）；
  - **T**（量化目标）：与 R 呼应的量化目标（如"准确率 ≥85%"），禁止无数字目标；
  - **A**（行动）：具体做法（方法/参数/工具），岗位任务侧重；
  - **R**（量化结果）：结果 ≥ T 目标（如"88%"）。
- **逻辑链判定**（新增规则审核 + LLM 复核）：
  - T 须从 S 痛点推导（可关键词/语义命中判定，LLM 兜底）；
  - R ≥ T 目标（数字对比，T/R 均在 items 中可提取时零 LLM 判定）；
  - S→T→R 任一断链 → blocker 触发重写。
- **现有衔接**：`bullet_limit` 保证条数 ≥4 的版本自然承载四段；审核由「⑦ 首条含基线数字」扩展为「前 4 条语义 + S 基线 + T 量化 + R 量化 + 逻辑链」。

### 2.2 详细度目标（适配约束 57/58 的「800 字」）

> latex-lab 是段落式（800 字上下）；resume_agent 是要点式（items/duties），**字数不直接迁移**，迁移的是「信息深度」判据。

- **每条要点达标判据**（全部满足视为「详细度达标」，否则按缺失项处理）：
  1. 结构完整：一条 = 做法/方法 + 关键参数或工具 + 量化结果（可一句话内完成）；
  2. 生产级细节：体现领域真实落地环节（如检索场景的切分参数/评测集规模、推理场景的并发/延迟/吞吐口径），**不泛泛而谈**——生成前置的 `search` 阶段（方法论 + 领域信息）即为此服务，生成时强制引用；
  3. 行数区间：一页 2~4 行/条、两页 3~6 行/条（沿用 mapping.json evaluation，作为渲染侧校验）；
  4. 岗位视角：内容侧重目标岗位承担的任务（呼应 `factsheet.coreSkills` + `jdFocus`），非全项目平铺。
- **条目过简判定**：无参数、无量化的"虚条"（如"负责系统开发"）→ 结构审核 blocker（与规则审核⑥量化检测联动）。

### 2.3 定量口径（迁移《简历数字口径与实现解释.md》）

- **强制口径**：每个量化数字须可回答「怎么来的」——口径 ∈ {评估集/受控压测/监控聚合/试点前后对比/团队统计}；LLM 生成时按此枚举自报口径。
- **合理性**：行业常规精度（沿用 `industry.metric_style`）+ 无极端值（实习生场景量级）——现有 ⑨ 保留并扩展「口径完备性」检查（无量纲数字如"性能大幅提升"→ blocker；口径缺失或与角色量级不匹配 → blocker）。
- **面试可辩护**：数字须经得起追问（被问口径能答出评估集/压测方案）。此要求与 prep_agent《附录_数字口径》联动（见 §四）。

### 2.4 公司脱敏（迁移约束 3，适配通用产品语义）

- **ai-created 项目**：不得虚构真实公司/机构/职级（现有 ⑦ 已含）；题材为课程/竞赛/自研等可验证类型。
- **需要"公司感"语境时**：用「某（行业）公司」匿名格式（如"某自动驾驶公司"），不虚构具体真实公司。
- **用户真实经历**：允许保留真实公司名（应届生自己的实习/项目），不做强制脱敏——与 latex-lab 的强制脱敏场景不同，后者面向投递规避雇主。

### 2.5 时间约束（迁移约束 7~13）

- **已有**：YYYY.MM 格式、end > start、2015.01~2030.12 区间（`validation.check_period`）。
- **迁移新增**（validation.py + 规则审核）：
  - 项目时间 ⊆ 某段实习时间（有实习时；无实习则项目独立，跳过匹配）；
  - 时间倒序排列（最晚在前：教育/实习/项目各自内部）；
  - 无重叠（教育间/实习间/项目间）。
- **违反处理**：以「修改项目时间（内容不变）」满足约束，不篡改用户事实（对齐 latex 约束 13）。

### 2.6 密度均衡（迁移约束 24）

- **组内相对**：实习 duties 组 / 项目 items 组，各条等效字数以组内最详细条为基准，比值 < 0.75 → blocker（防一详其余潦草）。
- **绝对下限**：单条等效字（实习要点 ≥45 / 项目条目 ≥35）。
- **口径**：等效字 = 中文 1.0 / ASCII ≈0.55（与 latex-lab `_eff_w` 一致），与行数区间双口径并行。

### 2.7 零截断与删减优先级（迁移约束 20~23）

- **零省略号**：整条保留或整条删除，渲染绝不截断句子（schema 500 字为输入上限，非渲染截断）。
- **STAR 四要素不删**：容量压缩只压缩 A（行动）条数与行数，S/T/R 恒渲染；弹性板块（照片/证书荣誉等）未填充自动删除。
- **容量不足顺序**：行距/密度收紧（`_content_usage` 降档）→ 压缩行动条数 → 删除弹性板块；仍不足才 WARN，不静默破坏底线。
- **✅ 适配决策点（已定稿 A，2026-08-17）**：一页版多项目时 `bullet_limit` 与「STAR 四段」的冲突，定稿方案 A——一页多项目也保持 4 条（S/T/A/R 各 1 条），与 latex-lab 约束 21「STAR 四要素禁止删除」一致；行动行数压缩，密度由 2.2 行数区间兜底。`bullet_limit` 已同步落地（一页恒 4 条）。

## 三、与审核维度对接（迁移落点）

### 3.1 规则审核（JL-Agent_改造设计 §3.2，7 项 → 扩展项）

| 新增 | 检查项 | 判定逻辑 | 对应 latex-lab |
|---|---|---|---|
| ⑧ | S→T→R 逻辑链 | T 回应 S 痛点、R ≥ T 目标（T/R 可提取时零 LLM） | 约束 6 |
| ⑨ | 时间约束 | 倒序 / 无重叠 / 项目⊆实习（validation.py 扩展） | 约束 7~13 |
| ⑩ | 密度均衡 | 组内相对 ≥0.75 + 单条绝对下限（等效字） | 约束 24 |
| ⑪ | 数字口径 | 每个数字带口径枚举；无量纲/量级失配 → blocker | 《数字口径》 |

### 3.2 LLM 审核（§3.3，4 项 → 扩展）

| 新增 | 维度 | 审核要点 | 对应 latex-lab |
|---|---|---|---|
| ⑪ | 内容质量评审 | 在 ⑦⑧⑨ 之上做整板块质量复核：完整性（STAR 四段 + 逻辑链断点）、价值性（岗位视角叙事）；沿用 verdict/score 输出，不新增独立评审器 | 约束 57/58 + `_REVIEW_SYSTEM` 四维 |

> 说明：latex-lab 独立 LLM 四维评审（准确性/完整性/逻辑性/价值性）在 JL 中**不新增独立评审节点**，而是映射到现有维度补齐——准确性=⑦ 事实一致 + ⑨ 量化合理；完整性=⑦ 结构 + ⑧ 逻辑链 + 2.2 详细度；逻辑性=⑧；价值性=⑧ JD 契合 + 2.2 岗位视角。避免机制膨胀（对齐 prep_agent「Critic = 规范裁判 + 锚点校验器」定位，LLM 审确定性/可交叉验证项）。

## 四、与 prep_agent 的联动（数字口径共享）

- resume 量化数字的**口径标注**（§2.3 结构化输出）作为 prep_agent《附录_数字口径》的**输入事实表**——resume_agent 生成即沉淀口径，prep 直接消费，避免两侧各写口径、口径不一致。
- 面试追问话术：prep 对 resume 数字生成「被追问时的回答方案」（展开式），数据源 = 本规范的 §2.3 口径标注。
