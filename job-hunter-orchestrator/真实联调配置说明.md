# JobHunter 单仓库自包含 · LLM 配置说明

> 适用范围：`RUN_MODE=real`（真实 LLM 端到端）。
> Key 方案（2026-08-18 拍板）：**用户自带 Key**——clone 本仓库到本地即含完整功能，仅需配置自己的 LLM Key，不做服务端托管/认证。
> **JOBHUNTER 单仓库自包含**：简历生成（resume_agent）、岗位匹配（match_agent）、面试材料（prep_agent）三组件进程内调用，投递跟踪（tracker_agent）本地 JSON 存储——**不依赖任何外部服务**。

---

## 1. 唯一要配置的东西：大脑 LLM Key

**位置**：`D:\TRAE\WORKSPACE\JobHunter\job-hunter-orchestrator\.env`（复制 `.env.example` 后填写）

```dotenv
# OpenAI 兼容接口，任选一家厂商（推荐 DeepSeek）
LLM_API_KEY=sk-xxxxxxxxxxxxxxxx
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-v4-flash
LLM_PROVIDER=deepseek

# mock=本地模拟（无需 Key，开箱即用）/ real=真实 LLM（需上面的 Key）
RUN_MODE=real
```

也可以在界面「控制台 → API Key」中配置（会自动写入同一处，即时生效）。

## 2. 验证

```powershell
cd job-hunter-orchestrator
uvicorn web.app:app --host 127.0.0.1 --port 2025
```

- `http://127.0.0.1:2025/api/health` 的 `mode` 应为 `real`。
- 走完整链路（简历生成 → 岗位匹配 → 面试材料 → 投递清单 → 跟踪），观察日志无降级警告即真实 LLM 生效。

## 3. 无 Key / 组件异常时的行为（不阻塞）

| 场景 | 行为 |
|---|---|
| 未配 Key 且 `RUN_MODE=mock` | 组件 mock 后端 / 占位 LLM，全流程本地模拟，无需 Key |
| `RUN_MODE=real` 但组件异常 | 节点内确定性降级：骨架简历（N3）/ 规则匹配（N4）/ 预置材料（N6），并记入 state.errors，不中断流程 |
| N1 画像解析 LLM 失败 | 自动降级为关键词规则解析 |
| N7 差距分析 LLM 失败 | 降级为预置样例 |
