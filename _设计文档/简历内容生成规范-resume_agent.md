## 二、内容生成标准

### 2.1 数量硬性约束（JL-Agent §6.4）

**常驻 / 非常驻板块分类**：
| 板块 | 分类 | 处理规则 |
|---|---|---|
| 个人信息（含照片） | 常驻 | 始终显示，不可删不可压 |
| 自我评价 | 常驻 | 始终显示；句数 1~3 句、内容层弹性可调 |
| 教育背景 | 常驻 | 始终显示，1~3 条由用户决定 |
| 项目经历 | 常驻 | 始终显示（无输入时 AI 创造）；条数/要点数/详略可调 |
| 技能特长 | 常驻 | 必填始终显示；内容分类/JD 拓展由生成引擎决定 |
| 实习经历 | 非常驻 | 未填自动隐藏（**输入上限 2 段**）；显示时要点数/详略可调 |
| 证书荣誉 | 非常驻 | 未填或用户选择时隐藏 |

**数量硬性约束（v0.5 定稿）**：项目条数由「目标页数 + 实习经历条数」硬性决定，**不随空间动态增减**：

| 实习经历条数 | 一页版项目条数 | 两页版项目条数 |
|---|---|---|
| 0（无实习经历） | 2 | 3 |
| 1 | 1 | 2 |
| 2 | 1 | 1 |

- 实习经历输入最多 2 段（表单上限），故表中实习条数最大为 2；
- 逻辑：实习与项目为互补的描述性内容——实习越少、项目越多（无实习时项目补足内容量，有实习时项目让位）；
- 约束优先于溢出压缩/不足扩充：压缩时**不减少项目条数**（只压缩每条要点数与详略），扩充时**不增加项目条数**（只增加每条要点数与详略）。

**溢出压缩顺序**（从先到后）：按 criticality 从低到高裁剪非常驻条目（low→medium）→ 主导板块内容层降档（详细→标准→精简，减少要点/句数）→ 合并项目要点 → 精简自我评价（保留 critical 句）→ 排版层全局密度档（loose→normal→compact）→ 仍溢出则提示用户改选两页版。

**不足扩充顺序**（从先到后）：追加自我评价句子（至 critical 句数上限）→ 主导板块内容层升档（精简→标准→详细，增加要点/技术栈详情）→ 排版层全局密度档（compact→normal→loose）→ 仍不足则提示用户改选一页版。

### 2.2 内容关键性分级 criticality（JL-Agent §6.7）

生成/美化时给每条内容（项目、实习要点、自我评价句子、荣誉条目）标记关键性等级，作为动态适配的裁剪依据：
- `critical`：与 JD 直接相关、核心量化成果（**绝不裁剪**）；
- `high`：重要职责/成果；
- `medium`：一般描述；
- `low`：辅助信息（次要荣誉、泛化描述）。

裁剪按 low → medium → high → critical 顺序执行；排版层调整不改变内容关键性。

### 2.3 详细度目标（JL-Agent §6.8 评估第 5 项 + 本地等效字）

**每条要点达标判据**（全部满足视为「详细度达标」，否则按缺失项处理）：
1. 结构完整：一条 = 做法/方法 + 关键参数或工具 + 量化结果（可一句话内完成）；
2. 生产级细节：体现领域真实落地环节（如检索场景的切分参数/评测集规模、推理场景的并发/延迟/吞吐口径），不泛泛而谈——生成前置的 `search` 阶段（方法论 + 领域信息）即为此服务，生成时强制引用；
3. 行数区间（渲染侧校验，沿用 mapping.json evaluation）：一页 2~4 行/条、两页 3~6 行/条；
4. 岗位视角：内容侧重目标岗位承担的任务（呼应 `factsheet.coreSkills` + `jdFocus`），非全项目平铺。

**条目过简判定**：无参数、无量化的「虚条」（如"负责系统开发"）→ 结构审核 blocker（与规则审核⑥量化检测联动）。

**本地等效字下限（双口径并行）**：实习要点 ≥45 / 项目条目 ≥35（中文 1.0 / ASCII ≈0.55，与行数区间并行，见 §2.8）。

### 2.4 项目经历生成规则（JL-Agent §6.8）

**生成流水线**：JD 分析（§3.1.6 主题一致性规则）→ 项目类型匹配（下方映射表）→ 联网取证（真实生产环境的实施流程/技术栈/成果指标，失败降级不阻塞）→ STAR 自然段落生成（无 S/T/A/R 标识）→ 量化数值直接生成（合理数值 + 行业精度规则，如性能提升 12.5%、延迟降至 120ms、支持 800QPS；见 §五 规则层）→ **criticality 标注**（每条要点按与 JD 相关度与量化强度标记 critical/high/medium/low）→ 批判性审阅（§2.6）。

**规则文件**：`rules/projects/*.json`，独立于代码、版本化可迭代。

**项目类型 ↔ JD 方向映射表**：
| JD 方向 | 可生成项目类型 | 示例骨架 |
|---|---|---|
| AI Agent / LLM 应用 | 智能体系统、RAG 知识库、提示工程工具 | 智能客服 Agent、多模态竞品分析 Agent、企业知识库 RAG |
| 后端开发 | 业务系统、中间件、开放接口服务 | 高并发订单系统、消息队列中间件、开放平台 API |
| 算法 / 机器学习 | 模型训练与部署、推荐系统、CV/NLP | 商品推荐系统、图像分类推理服务、文本分类微调 |
| 数据分析 | 指标体系、BI 看板、数据挖掘 | 用户增长分析看板、流失预测模型、A/B 实验分析 |
| 前端开发 | 可视化大屏、组件库、低代码平台 | 数据可视化大屏、通用组件库、低代码表单引擎 |
| 非技术方向（产品/运营等） | **不创造**，仅美化真实经历 | —（无项目经历时该区块按 §三 隐藏） |

**评估标准（5 项）**：STAR 四要素齐备度；与 JD 关键技能词覆盖率；真实性自洽（技术栈/角色身份匹配，不虚构公司、职级、具体机构）；量化占比（每条 ≥1 个量化成果）；字数范围（一页版每条 2~4 行、两页版 3~6 行）。

**STAR 硬结构（本地 bullet_limit 落地）**：`ProjectItem` 平铺列表承载 S（背景基线，含一条基线数字）/ T（量化目标，与 R 呼应）/ A（行动，岗位侧重）/ R（量化结果，R ≥ T）；`bullet_limit(page_option, project_count)`——一页恒 4 条（S/T/A/R 各 1）、两页 ≤2 项目 6 条（S/T/A×3/R）、两页 ≥3 项目 4 条。S→T→R 任一断链 → blocker 触发重写。

### 2.5 量化与数值精度（JL-Agent §6.10 规则层 + 数字口径）

**数值直接生成规则**：数值合理、贴合行业口径与上下文；精度按指标类型——
- 百分比：取整数或 1 位小数；
- 延迟/时间：按量级取整（ms/s）；
- 吞吐/人数：取整（QPS/并发/人）；
- **禁止极端值**（如 1000% 提升、0 成本）。

**数字口径（本地强制）**：每个量化数字须可回答「怎么来的」——口径 ∈ {评估集 / 受控压测 / 监控聚合 / 试点前后对比 / 团队统计}；LLM 生成时按此枚举自报口径。无量纲数字（如"性能大幅提升"）或口径与角色量级不匹配 → blocker。此要求与 prep_agent《附录_数字口径》联动（§六.3）。

**行业精度**：沿用 `rules/industries/*.json` 的 `metric_style`（如互联网：性能提升 8%~15%（1 位小数）、延迟 100~200ms、数百 QPS；金融：坏账率降低 0.X%、AUC 0.9+）。

### 2.6 批判性审阅（JL-Agent §6.5）

生成后以 HR 视角对每个板块做审查，输出审查意见并驱动修订闭环：
- **关键性审查**：每条内容是否达到其 criticality 等级预期——critical 项是否真实存在且与 JD 强相关，缺失则提示补充；
- **匹配度审查**：技能/经历与 JD 关键词覆盖率（<60% 提示补充或调整表述）；
- **STAR 审查**：项目经历四要素是否齐备、行动与结果是否量化（无量化输出 WARN）；
- **真实性审查**：技术栈/角色/数字自洽，不虚构公司、职级、具体机构；
- **冗余审查**：同类描述合并建议，降低 low 级内容占比。

审查意见以 WARN/建议形式展示，用户可一键触发对应板块重生成。

### 2.7 真实性、脱敏与时间约束（JL-Agent §6.5 真实性 + 本地）

- **ai-created 项目**：不得虚构真实公司/机构/职级；题材为课程/竞赛/自研等可验证类型；需要「公司感」语境时用「某（行业）公司」匿名格式（如"某自动驾驶公司"）。
- **用户真实经历**：允许保留真实公司名（应届生自己的实习/项目），不做强制脱敏。
- **时间约束**：YYYY.MM 格式、end > start、2015.01~2030.12 区间（`validation.check_period`）；项目时间 ⊆ 某段实习时间（有实习时；无实习则项目独立）；教育/实习/项目各自内部时间倒序；无重叠。违反时以「修改项目时间（内容不变）」修复，不篡改用户事实。

### 2.8 密度均衡（本地保留）

- **组内相对**：实习 duties 组 / 项目 items 组，各条等效字数以组内最详细条为基准，比值 < 0.75 → blocker（防一详其余潦草）。
- **绝对下限**：单条等效字（实习要点 ≥45 / 项目条目 ≥35）。
- **口径**：等效字 = 中文 1.0 / ASCII ≈0.55（与 latex-lab `_eff_w` 一致），与行数区间双口径并行。

### 2.9 零截断与删减优先级（JL-Agent §6.4 溢出压缩顺序 + 本地）

- **零省略号**：整条保留或整条删除，渲染绝不截断句子（schema 500 字为输入上限，非渲染截断）。
- **STAR 四要素不删**：容量压缩只压缩 A（行动）条数与行数，S/T/R 恒渲染；弹性板块（照片/证书荣誉等）未填充自动删除。
- **容量不足顺序**：按 §2.1 溢出压缩顺序逐级执行（criticality 裁剪 → 内容层降档 → 合并要点 → 精简自我评价 → 排版层降档）；仍不足才 WARN，不静默破坏底线。

## 三、动态适配与收敛（JL-Agent §6.7）

**目标**：最终输出精确填满所选页数，避免任何页面下半部分大面积空白；当内容约为一页半时自动调整布局消除第二页下半部分空白。

### 3.1 稠密度两层机制
- **排版层稠密度——所有板块全局参与**：字号、行距、段落间距、区块间距、项目符号缩进等排版参数统一作用于全部板块，无例外（`body[data-density]` 驱动，参数见 §四）；
- **内容层稠密度——内容生成弹性**：同一内容可「展开讲详细 / 精简说简短」（详略档），且**数量**（项目条数、每条要点数、自我评价句数）本身即为弹性的重要组成部分；由生成引擎按目标页数 + criticality + 剩余空间决定详略与数量，主要作用于自我评价/实习经历/项目经历等描述性板块（教育/技能/证书等由用户输入决定的内容量固定，不参与内容层弹性）。

### 3.2 内容分区性质
| 板块 | 分类 | 排版层参与 | 内容层弹性 | 弹性策略 |
|---|---|---|---|---|
| 个人信息（含照片） | 常驻·固定 | 参与 | 否 | 内容量固定，不可增减 |
| 教育背景 | 常驻·固定 | 参与 | 否 | 1~3 条由用户决定，条目内内容固定 |
| 自我评价 | 常驻·弹性 | 参与 | **是** | 句数 1~3 句、每句详略可调 |
| 实习经历 | 非常驻·弹性 | 参与 | **是** | 未填整块隐藏；要点数、每条详略可调 |
| 项目经历 | 常驻·弹性 | 参与 | **是** | 条数（硬性规则 §2.1）、每条要点数、详略可调 |
| 技能特长 | 常驻·固定 | 参与 | 否 | 内容分类/JD 拓展由生成引擎决定 |
| 证书荣誉 | 非常驻·固定 | 参与 | 否 | 未填或用户选择时整块隐藏 |

### 3.3 调整手段
- 排版层（全部板块，全局统一）：字号在**预设范围内**微调（一页 9.5~10.5pt、两页 10.5~11.5pt，以基线为中心 ±0.5pt）；区块间距 `--gap`、行距 `--lheight`、要点间距联动；列表缩进微调（一页 10~18px、两页 12~20px）；三档 compact / normal / loose。
- 内容层（描述性板块，生成引擎控制）：详略档（详细 / 标准 / 精简）；数量档（项目条数、每条要点数、自我评价句数）；依据 = 目标页数 + criticality（critical 项必保）+ 剩余空间。

### 3.4 适配机制（构建期，分三层）
1. **内容侧约束**（生成时）：项目条数先按 §2.1 数量硬性约束定死（实习 0/1/2 → 一页 2/1/1、两页 3/2/1），再按目标页数 + criticality 决定其余详略与数量——一页版：每条 2~3 要点、自我评价 1~2 句、详略精简；两页版：每条 3~4 要点、自我评价 2~3 句、详略标准；生成内容「宁多勿少」，交由排版侧压缩。（描述性板块按目标页数可用高度做**高精度空间预算**：模型篇幅自估 + 实测校准，见 §2.10-L7）
2. **排版侧微调**（渲染后测量）：以关键路径（critical path）为指导——内容量最大的弹性板块为主导板块，优先调整其排版层密度——超页按 §2.1 溢出压缩顺序逐级压缩；不足按 §2.1 不足扩充顺序逐级扩充。
3. **显隐侧整合**：非常驻板块（实习经历、证书荣誉）未填写或用户选择时自动隐藏；隐藏后整体布局自动收缩重排，保证无空洞。

### 3.5 页数判定与收敛参数
- **页数判定**：目标页数 = 用户勾选的分页选项（一页 / 两页），**由用户直接决定，不通过内容测量推断页数**；动态适配只负责把内容收敛到用户所选目标页数。
- **收敛（参数定稿）**：`渲染 → 测量 → 调整 → 重渲染`，**最多 3 轮**收敛到目标页数；填充判定——末页填充度 **≥85% 视为填满**、**75%~85% 可接受**、**<75% 触发扩充**、**>100% 触发压缩**（两页版以第 2 页为准）；仍无法收敛时优先保证不溢出（宁可紧凑，不可溢出）。

## 五、行业模板库与 Prompt 组装（JL-Agent §6.10）

### 5.1 行业大类模板库
`rules/industries/*.json`，20 个大类可扩展；已落地 5 个核心行业：互联网/人工智能、金融、快消/零售、制造业/工业、游戏/数字内容。

**模板条目结构**：
| 字段 | 说明 |
|---|---|
| `industry` | 行业大类名称 |
| `keywords` | 行业高频能力/技术词（HR 关键词匹配、ATS 命中） |
| `skills` | 该行业典型技能分类建议（专业技能/工具/语言） |
| `metric_style` | 成果量化口径与数值精度建议 |
| `tone` | 表述风格倾向（如金融严谨、互联网技术驱动） |
| `notes` | 行业注意事项（如金融勿夸大合规经验、实习生强调学习能力） |
| `project_types` | 该行业可生成的项目类型（对接 §2.4 映射表） |

### 5.2 Prompt 优化双维度
1. **用户视角**：从表单数据 + 岗位/JD 精确捕捉用户需求——目标岗位（岗位名/JD/职业方向）、身份（实习生/全职）、可用经历（实习/项目/技能/荣誉）、分页选项、照片有无；缺失信息以占位符呈现并提示补填，不臆造；
2. **HR 视角**：可量化成果优先、STAR 自然段落、JD 关键词命中、ATS 关键词友好、行业用词准确（注入行业模板库）、克制不夸大（HR 厌恶失真内容）；并批判性自审——生成后以 HR 视角自查每条内容的关键性、匹配度、真实性与冗余（对接 §2.6）。

### 5.3 八层 Prompt 组装顺序（prompts.py）
1. **系统身份层**：专业简历撰写助手，遵循 ATS 规范、STAR 融入自然段落（不显示 S/T/A/R 标识）、合规边界（实习经历不创造、项目创造带合理量化数值）；
2. **规则层**：数值直接生成规则（§2.5 数值精度；禁极端值）、技能必填/拓展、身份差异化（实习生/全职）、简历不展示目标岗位字段、字数/要点数范围（按分页选项）、**criticality 标注规则**（与 JD 相关度 + 量化强度 → critical/high/medium/low）；
3. **行业上下文层**：按职业方向匹配并注入对应行业模板库条目（keywords/skills/metric_style/tone/notes/project_types）；
4. **用户数据层**：基本信息、教育、实习、项目、技能、荣誉、照片；
5. **JD 分析层**：主题一致性校验结果、核心技能词、岗位侧重（§3.1.6 规则产出）；
6. **联网资料层（可选）**：真实行业案例与成果指标（§6.6 双模搜索产出）；
7. **批判性自审层**：生成后以 HR 视角审查关键性/匹配度/STAR/真实性/冗余（§2.6）；
8. **输出约束层**：按板块结构化输出、内容量匹配分页选项（项目条数按 §2.1 数量硬性约束）、每条内容携带 `criticality` 字段、JSON 结构约定。

## 六、与审核维度对接

### 6.1 规则审核（确定性，零 LLM）
| 检查项 | 判定逻辑 | 依据 |
|---|---|---|
| ⑥ 量化检测 | 每条 ≥1 个量化成果（含口径枚举 §2.5）；无量纲/量级失配 → blocker | §2.5 |
| ⑧ S→T→R 逻辑链 | T 回应 S 痛点、R ≥ T 目标（T/R 可提取时零 LLM） | §2.4 |
| ⑨ 时间约束 | 倒序 / 无重叠 / 项目⊆实习（validation.py 扩展） | §2.7 |
| ⑩ 密度均衡 | 组内相对 ≥0.75 + 单条绝对下限（等效字） | §2.8 |
| ⑪ 数字口径 | 每个数字带口径枚举；无量纲/量级失配 → blocker | §2.5 |

### 6.2 LLM 审核（内容质量评审）
在 ⑥⑧⑨⑩⑪ 之上做整板块质量复核：完整性（STAR 四段 + 逻辑链断点）、价值性（岗位视角叙事）；沿用 verdict/score 输出，不新增独立评审器。JL-Agent 四维评审（准确性/完整性/逻辑性/价值性）映射：准确性=⑦ 事实一致 + ⑨ 量化合理；完整性=⑦ 结构 + ⑧ 逻辑链 + 2.3 详细度；逻辑性=⑧；价值性=⑧ JD 契合 + 2.3 岗位视角。

### 6.3 与 prep_agent 联动（数字口径共享）
- resume 量化数字的**口径标注**（§2.5 结构化输出）作为 prep_agent《附录_数字口径》的**输入事实表**——resume_agent 生成即沉淀口径，prep 直接消费，避免两侧各写口径、口径不一致。
- 面试追问话术：prep 对 resume 数字生成「被追问时的回答方案」（展开式），数据源 = §2.5 口径标注。
