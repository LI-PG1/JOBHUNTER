> 配套：`4_大改造架构设计-v2.0.md` §0.5.3（投递=人工环节）/ §5.3（N9 投递执行）/ §5.5.6（版本注册表）/ §6.1（match_agent 契约）
> 导出范本：`D:\TRAE\WORKSPACE\投递\深圳AI岗位目标公司清单_实习版_横版.html`（用户导出的岗位清单格式，Q10e 已学习）
> 输入范本：JS-Agent 前端岗位匹配（`projects/JS-Agent/frontend/index.html`，城市/生成条数/企业类型多选/画像四参数，Q10f 已学习）
> 定位：match_agent **只出候选**，用户**终选**——投递清单是大脑在 N9 展示给用户的**结构化推荐岗位清单**，作为用户挑选投递的依据。清单**只推荐、不引导**。

## 1. 定位与边界

| 项 | 定义 |
|---|---|
| 生产者 | **大脑节点**（不是 match_agent 内部产物——match_agent 只输出 `match_results` 候选，§6.1） |
| 展示点 | 大脑 N9「投递确认」interrupt 时展示（§0.5.3 / §5.3） |
| 消费方 | ① 用户（查看参考，**自行独立投递**）② prep（只对**已投**岗位生成材料，§0.5.3）③ 大脑报告（只读汇总 tracker 数据） |
| 不做什么 | **不替用户投递**（JobHunter 无代投功能，投递由用户独立完成于系统外）；**不自动写 tracker**（面试跟踪信息由用户手动录入，大脑只读）；不提出投递数量/节奏建议（无上限、无"优先投哪个"引导）；**不参与简历版本绑定**（版本对应在 N4 JS 岗位筛选时已明确，清单继承） |

**边界**：投递清单是"结构化推荐 + 用户挑选状态"的工作台状态。长期看板（已投/约面/结果）由 tracker 维护（§0.6.3 C3）。

## 2. 生成逻辑

### 2.1 生成时机与位置

> Q10f 确认（2026-08-17）：投递清单**不需要用户先选岗位**——用户只需提供
> 「简历（系统解析）+ 城市 + 生成数量 + 企业类型（多选）」四项输入，
> 大脑据此生成清单。输入方式对齐 JS-Agent 前端岗位匹配
> （`projects/JS-Agent/frontend/index.html`：城市 select / 生成条数 select / 企业类型多选 chips / 画像 textarea）。

```
方式 ① 全流程联动：N5 质量判定 pass（或 accept_with_issues 降级）
         → 投递清单生成（复用已解析简历/画像与用户在前端填写的四项条件）
方式 ② 独立生成（前端「投递清单」板块）：用户选定简历版本 → 填四项条件 → 直接生成
  → N9 投递确认（interrupt：展示清单供用户参考，不自动投递）
  → 用户自行投递（系统外操作）→ 手动录入 interview-tracker
  → prep 按已投岗位生成材料（以用户确认的投递为准）
```

> 与 v2.0 §0.5.3「面试准备的输入是已投递岗位」对齐——投递确认应在 prep 之前。当前 JobMaker 骨架的「定稿确认」在「面试准备」之后，属骨架版简化顺序，Q10 落地时调整。

### 2.2 输入（Q10f 四项）

| 输入 | 类型 | 来源/示例 | 用途 |
|---|---|---|---|
| `profile`（简历解析） | 必填 | N1 画像解析 / 用户选定简历版本解析（技能/项目/方向） | 匹配打分依据 + 展示上下文 |
| `city`（城市） | 必填 | 单选，如「深圳」（对齐 JS select） | 岗位地区过滤 |
| `max_results`（生成数量） | 必填 | 单选 10/20/30/40/50/100（对齐 JS select，默认 20） | 候选收录上限 |
| `company_types`（企业类型） | 必填，**多选** | 枚举见 §3.4，默认全选（对齐 JS chips） | 企业规模/性质过滤 |

> 相比 JS-Agent：`company_types` 增加 **外企**（共 6 类：央企 / 国企 / 大型 / 中型 / 小型 / 外企）；
> `profile_text` 由用户手填改为**简历自动解析**（用户选定简历版本后系统解析技能/项目/方向）。

### 2.3 处理流程（规则为主，LLM 仅润色理由）

```
输入：profile(解析) + city + max_results + company_types
  → ① 候选      按四项条件搜索/筛选岗位（渠道枚举见 §3.4；复用 JS 搜索回路能力或 match_agent 候选）
                收录 ≤ max_results
  → ② 打分      规则打分：技能-JD 关键词重叠 + 简历项目/方向匹配 + 城市命中 + 企业类型命中
  → ③ 排序      final_score 降序（主）；同分按时效新（fresh_days 内）优先（次）
  → ④ 展示分档  按分数分档仅作视觉分组，纯信息不构成投递建议：
               P0: final_score ≥ 90
               P1: 80 ≤ final_score < 90
               P2: accepted 且 < 80
  → ⑤ 理由     聚合 reasons（规则原因）+ 时效/企业档标注；
               LLM 润色为 ≤50 字投递理由（LLM 异常 → 用 reasons 摘要，不阻塞）
  → ⑥ 汇总     summary：总数 / 分档计数 / 渠道计数 / 版本计数
```

**明确排除**：无投递数量/节奏建议、无"P0 优先投"类引导——用户自己决定投哪些、何时投（Q10c 确认）。

**LLM 参与度**：仅 ⑤ 理由润色（可降级）。打分/排序/分档全部规则确定性执行——投递清单是给用户看的"推荐"，清单阶段不引入第二次不确定判定。

### 2.4 岗位 ↔ 简历版本对应（N4 明确，清单继承）

> Q10d 确认：投递清单**不参与**版本决策；版本对应关系在 **JS 岗位筛选时**（N4 match_agent）明确。
> Q10e 补充：**导出/展示时一次只对一个简历负责**——用户在生成清单前先选定所用简历版本，清单只对该版本的收录岗位生成；不在同一份清单中混排多个版本的岗位。

```
N4 JS 岗位筛选（输入含简历版本线信息）
  → 每个收录岗位绑定 resumeVer：基于哪个版本简历筛出的该岗位
  → 无匹配版本线 → "pending_version"（N4 阶段标记，§5.5.6 不猜，用户后续选版）
  → match_results 每项内嵌 resumeVer（§6.1 契约扩展）
投递清单生成时直接继承，不做版本匹配/重绑定
导出动作（N9 或用户请求）：用户先选定 resumeVer → 只导出该版本的岗位清单
```

## 3. 数据结构定义

### 3.1 大脑 State 字段（JobHunterState 新增）

```python
submission_plan: Dict[str, Any]   # 投递清单（N9 前置生成，interrupt 展示）
```

### 3.2 SubmissionPlan（顶层）

```jsonc
{
  "submission_plan": {
    "generated_at": "2026-08-15T10:00:00+08:00",
    "status": "pending_review",          // pending_review → confirmed / cancelled
    "items": [ SubmissionItem, ... ],    // 按 final_score 降序（同分时效优先）
    "summary": {
      "total": 10,
      "by_tier": { "P0": 3, "P1": 5, "P2": 2 },
      "by_channel": { "招聘平台": 6, "官网": 3, "社区": 1 },
      "by_resumeVer": { "line-aiinfra-v2": 8, "pending_version": 2 }
    }
  }
}
```

### 3.3 SubmissionItem（清单项）

```jsonc
{
  "job_id": "J-007",
  "title": "大模型推理优化工程师",
  "company": "示例公司",
  "city": "上海",
  "channel": "招聘平台",                  // 枚举：招聘平台 / 官网 / 社区（沿用 §2.3）
  "source_url": "https://...",
  "final_score": 92,                      // N5 判定后分数
  "fits": { "jd_fit": 0.8, "quality": 0.6 },   // LLM 软性维度（仅展示，§1.6）
  "resumeVer": "line-aiinfra-v2",         // ★ 继承自 N4 match_results（清单不参与版本决策）
  "tier": "P0",                           // 展示分档（纯信息，无投递建议语义）
  "reason": "强匹配：技能线全覆盖 + 同城 + 时效新",   // ≤50 字（LLM 润色，可降级）
  "reasons": ["技能匹配度高", "同城"],      // 规则原因摘要（降级时即投递理由）
  "user_action": "suggested",             // 用户参考标注：suggested → skipped（§3.5，不驱动投递）
  "applied_at": null
}
```

### 3.4 枚举总表

| 字段 | 枚举 | 说明 |
|---|---|---|
| `tier` | `P0 / P1 / P2` | **展示分档**（视觉分组，不构成投递建议，§2.3④） |
| `user_action` | `suggested / skipped`（可选标注） | 用户参考标注，不驱动投递（§3.5） |
| `channel` | `招聘平台 / 官网 / 社区` | 沿用 match_agent 渠道枚举 |
| `resumeVer` | `line-<方向>-v<N>` / `pending_version` | 版本 ID（D11）；**N4 绑定，清单继承** |
| `company_types`（Q10f） | `央企 / 国企 / 大型 / 中型 / 小型 / 外企` | 企业类型多选（含新增**外企**），§2.2 输入 |
| `city` | 任意城市（单选） | §2.2 输入 |
| `max_results` | `10 / 20 / 30 / 40 / 50 / 100` | 生成数量（§2.2 输入，默认 20） |
| `status`（plan 级） | `pending_review / confirmed / cancelled` | 清单生命周期 |

### 3.5 用户挑选标注（清单上的参考标注，不自动写 tracker）

```
suggested ──用户标注──→ skipped（参考清单上标记跳过，可带 reason）
    └──用户自行投递（系统外）→ 在 interview-tracker 手动录入
```

- `user_action` 只是清单上的**用户参考标注**（可选），不驱动任何系统投递动作
- 投递进度以 tracker 中**用户手动录入**的记录为准；大脑不自动写 tracker
- `applied_at`：清单项被用户标注"已投"的时间（用户反馈/标注，非系统检测）

### 3.6 与 tracker 的关系（用户手动录入，大脑只读）

```
用户投递完成（系统外：BOSS/官网/内推等）
  → 用户在 interview-tracker 手动录入投递/面试记录
  → 大脑只读汇总 tracker 数据（投递看板/总报告），不自动写入
```

> 纠偏（2026-08-15）：JobHunter **无替用户投递功能**；投递由用户独立完成；tracker 信息由用户手动录入。原"大脑确认后写回 tracker"设计作废。

## 4. 导出呈现（HTML 岗位清单 · Q10e）

> 用户已有自行导出的岗位清单格式范本：`D:\TRAE\WORKSPACE\投递\深圳AI岗位目标公司清单_实习版_横版.html`
> 大脑投递清单导出**复用该格式**（视觉系统 / 表格模式 / 打印适配），内容映射见 §4.3。

### 4.1 导出定位

| 项 | 定义 |
|---|---|
| 形态 | 单文件 HTML（无外部依赖），A4 横向打印即得纸质/PDF 清单 |
| 数据源 | `submission_plan.items`（Q10f 四项输入生成，已按 final_score 排序、tier 分档，§2.3） |
| 简历视角 | **单版本**：导出前用户先选定 resumeVer，只导出该版本岗位（Q10e，§2.4） |
| 边界 | 导出仅**呈现**，不写 tracker、不触发投递、无数量/节奏引导（§1 边界延续） |

### 4.2 复用的范本格式要素（来自 `深圳AI岗位目标公司清单_实习版_横版.html`）

| 要素 | 范本实现 | 大脑导出映射 |
|---|---|---|
| 页面 | `@page { size: A4 landscape; margin: 10mm 8mm; }` + `@media print`（隐藏 toc / 保色 / thead 跨页重复 / tr 防截断） | 同左 |
| 视觉系统 | CSS 变量色板（primary `#1B3A5C` / accent `#0E9F8B` / 三色状态）/ 字号 / 间距 / 圆角 | 同左 |
| hero 页眉 | 渐变页眉：标题 + meta 行 + tags 胶囊 | 标题 = 「<简历版本> 投递清单」；meta = 生成时间 / 简历版本 / 画像摘要；tags = 技能线 / P0·P1·P2 计数 |
| toc 目录 | 章节锚点 pills | 按 tier 分组锚点（P0 / P1 / P2 / 来源） |
| legend 图例 | 技能线标签（skill-app 绿·应用 / skill-inf 紫·推理 / skill-both 黄·双线）+ 状态标注 | 同左（技能线标签 = resumeVer 方向线） |
| blockquote 导读 | 章节开头说明框 | tier 分组导读（该档含义，纯信息非引导） |
| 表格 | 表头深蓝底白字 / 斑马纹 / 首列公司名固定样式 | 列：公司·岗位 / 城市 / 渠道 / 匹配分 / 理由 / 链接 |
| sources 来源 | 双栏列表，逐条可溯源 | 每项 source_url + reasons |

### 4.3 内容映射（SubmissionItem → HTML）

```
按 tier 分组为三个表格（P0 / P1 / P2），组内按 final_score 降序
每组表头列：
  # | 公司 · 岗位 | 城市 | 渠道 | 技能线(resumeVer) | 匹配分 | 推荐理由(≤50字) | 来源链接
  末行或页眉 summary：该档数量
文末 sources 区：全部 source_url 双栏 + 生成时间 + 版本
```

| 列 | 来源字段 | 备注 |
|---|---|---|
| 公司 · 岗位 | company + title | 首列固定样式（nowrap / 加粗 / 居中） |
| 城市 | city | — |
| 渠道 | channel | 枚举：招聘平台 / 官网 / 社区 |
| 技能线 | resumeVer（line-app / line-inf / 双线） | 映射 skill-app / skill-inf / skill-both 标签 |
| 匹配分 | final_score | P0≥90 / P1 80-90 / P2<80 |
| 推荐理由 | reason（LLM 润色 ≤50 字） | 异常降级为 reasons 摘要 |
| 来源链接 | source_url | 可点击，word-break: break-all |
| 用户状态（可选列） | user_action / applied_at | suggested→skipped / 已投时间，导出时标注 |

### 4.4 导出动作与入口

```
入口 ① N9 投递确认 interrupt 展示清单时，同步提供「导出 HTML」下载链接
入口 ② 前端「投递清单」板块：用户选定 resumeVer → 导出按钮 → 下载单文件 HTML
产物  投递清单_<resumeVer>_<YYYYMMDD>.html（A4 横向可打印）
```

- 文件名规则：`投递清单_<resumeVer>_<YYYYMMDD>.html`
- 生成方式：大脑节点/前端工具用模板渲染（复用范本 CSS 块），无 LLM 参与（确定性）
