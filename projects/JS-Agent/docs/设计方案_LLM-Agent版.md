## 1. 设计思路

```
四步用户流程：配置APIKEY → 提供个人信息 → 点击开始匹配 → 查看匹配结果
                              │
                              ▼
┌─ Agent 循环（ReAct：思考→工具→观察→再思考）──────────────┐
│ ① 画像解析（LLM 理解 → 规则库校验成「画像卡」，补全隐含技能）│
│ ② 搜索规划（LLM 决定关键词 + 来源组合，≥3 轮迭代）        │
│ ③ 执行搜索（自动选择搜索后端 + fetch 多级回退）           │
│ ④ 数据洗涤（去重 · 去噪 · 时效 · 地域 · 企业类型过滤）     │
│ ⑤ 判断筛选（LLM 判断 + 规则库收录标准，80% 匹配阈值）      │
│ ⑥ 匹配度 ≥90% → 自动扩散同类岗位搜索                     │
│ ⑦ 排序（规则打分 + LLM 复核交叉验证）                    │
│ ⑧ 生成清单（LLM 生成 → JSON Schema 校验 → md/HTML）      │
│ ⑨ 自我审查（规则质检 + LLM 复核 → 未达标则修正循环）       │
└───────────────────────────────────────────────────────┘
      规则库 = 强约束层（贯穿 ①②⑤⑥⑦⑧⑨）
```

## 4. 插件系统（v0.5 修订：双按钮交互）★

### 4.1 通用插件定位（沿用）
- `search`：智谱 Web Search（模型内置）→ 阿里百炼 → Tavily → ddgs
- `fetch`：Jina Reader → Trafilatura → Playwright（兜底）
- 站点差异走 `sites.py` 规则；多插件架构仅作备选

### 4.2 灰区操作原则（意见 5）★
- **总体授权**：在保证系统安全与核心合规（不盗取凭据、不破坏数据、遵循基本网络道德）的前提下，允许有限灰区操作以优化用户体验与功能可用性
- 适用：非官方/灰色地带 CLI（boss-zhipin-scraper 类 Chrome CDP 工具、ddgs 等）、非常规安装方法（pip/GitHub Release/二进制）
- 安全红线：涉及登录态由用户自行配置 Cookie；不代填凭据；不执行用户未授权的数据操作

### 4.3 插件管理交互（意见 6）★

插件管理区（悬浮控制台内）两个按钮：

| 按钮 | 行为 |
|------|------|
| **一键配置** | 自动执行完整配置流程：探测 → 安装缺失依赖（自动选源）→ 配置 → 自检 → 展示状态 |
| **一键卸载** | 自动移除所有插件相关配置：卸载已安装组件 → 清除配置与缓存 → 恢复默认 → 展示状态 |

**交互状态**：
- 点击任一按钮后，**两个按钮同时置灰（disabled）**
- 实时状态提示「配置中...」/「卸载中...」（进度文案）
- 完成后按钮恢复可用，状态卡展示最终结果（已就绪 / 失败原因）

## 5. 强约束三层网关（沿用 v0.4，含正式批准项）

### 5.1 第一层：搜索前 · 画像锚定 Gate
- 画像卡字段：技能（本体校验防幻觉）、**隐含技能补全（强制，标"待确认"，✅ 批准实施）**、学历、毕业时间、城市、经验年限（可空）、**企业类型（五档多选）**
- 校验不通过 → 反馈重生成（≤2 轮）

### 5.2 第二层：搜索中 · 采集收录 Gate（✅ 阈值批准实施）
1. **技能匹配度 ≥ 80% 收录；60-80% 收录标「补足」；<60% 淘汰；≥90% 自动扩散**
2. **企业类型过滤（意见 1/4）**：按用户所选（央企/国企/大型/中型/小型，多选）过滤，判定标准 §9
3. JD 技能密度 ≥ N；时效 ≤ 2 个月；地域匹配；来源可信度分级；字段完整

### 5.3 第三层：生成后 · 输出质检 Gate（不变）
字段完整 → 打分交叉验证 → 事实约束 → 技能线一致；失败自我修正 ≤3 轮

### 5.4 非完美匹配引导（不变）
60-80% 岗位标识「需补足」+ 缺失技能/经验差距/补足建议

### 5.5 约束强度（不变）
严格（默认）/ 标准 / 宽松，控制台切换

## 6. Agent 循环与搜索策略（沿用）

- 最低 3 轮迭代 + 必覆盖 3 类来源（招聘平台/官网/社区）
- 质量指标：条数 ≥ 用户选择×1.5、来源 ≥3 类、时效 ≥60%、双线覆盖
- 动态步骤：基础 3 轮 → 自适应加轮 → 收敛（达标 / 连续 2 轮无新增 / 上限 10 轮）

## 7. 搜索后端自动选择（沿用）

- 启动自动探测可用后端 → 自动生成优先级；运行时自动回退；控制台只读状态卡透明展示
- 优先级：模型内置（智谱）→ 用户本地浏览器（粘贴导入）→ Tavily → ddgs → Playwright（需确认下载 ~150MB）

## 9. 企业类型判定标准（意见 1/4，**提交审核**）★

> 5 档分类：**央企 / 国企 / 大型 / 中型 / 小型**，同级多选。判定优先级：**央企 → 国企 → 大型 → 中型 → 小型**（先判性质，再判规模）。

### 9.1 判定维度与量化指标

| 档位 | 判定标准（满足任一即归入） |
|------|---------------------------|
| **央企** | 国务院国资委监管的中央企业（含金融央企），如国家电网/中石化/中国电子/招商局/华润/中广核等，以国资委央企名录为准 |
| **国企** | 地方政府或地方国资控股的企业（如深圳能源/深智城/华润数科属地子公司等），国有资本控股 |
| **大型** | 员工 > 5,000 人 或 年营收 > 500 亿元 或 上市市值 > 500 亿元 或 世界/中国 500 强 |
| **中型** | 员工 500-5,000 人 或 年营收 10-500 亿元 或 融资 C 轮及以上 或 细分行业龙头；**独角兽（估值 > 10 亿美元）统一归入中型**（意见 4） |
| **小型** | 员工 < 500 人 且 年营收 < 10 亿元 且 融资 C 轮以前（未达中型标准） |

### 9.2 判定逻辑
1. 先判企业性质：央企名录命中 → 央企；否则国资控股 → 国企
2. 非央国企按规模判定：满足大型任一指标 → 大型；否则中型任一指标（含独角兽）→ 中型；否则 → 小型
3. 数据来源优先级：企业官网/财报 > 国资委名录 > 企查查/天眼查 > 招聘页公司介绍 > 媒体

### 9.3 待审核问题
- 央企/国企独立成类后，大型档是否排除央国企？（当前判定逻辑：央国企优先判定，规模档仅适用于非央国企）
- 独角兽统一归中型，是否还需在结果中标注"独角兽"？（建议保留标注便于识别）
- 五档是否够用？是否需要"超大型"细分？
