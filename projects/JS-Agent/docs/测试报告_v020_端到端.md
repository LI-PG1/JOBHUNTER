## 三、关键修复记录

1. **技能本体 id 匹配**（gates.py）：画像技能与 JD 技能统一按本体技能 id 匹配，不再按名称字符串精确对比（"vLLM" 不再失配于本体名 "vLLM 推理服务"）。
2. **词边界匹配**（providers.py `match_skills`）：纯 ASCII 词条改用词边界正则，修复 "llm" ⊂ "vLLM" 的误命中——此前画像技能 "vLLM" 会额外命中「大模型基础」，扭曲匹配度（4/5=80 误判）。
3. **企业分类器**（enterprise.py）：`__init__` 预初始化 `self.names`，修复 AttributeError（原仅在有 rules/enterprise.json 时才赋值）。
4. **时效消息规范化**（gates.py）：排除原因统一为「已超过时效（N 天）：日期」，便于质检与展示。

## 四、全量优化记录（角色卡驱动，2026-08-11）

### 核心逻辑缺陷修复（影响结果质量）

| 编号 | 缺陷 | 修复 |
|------|------|------|
| G1 | **企业类型过滤形同虚设**：loop 构造的 entry 无 `enterprise_type`，judge 中永远"未知"，用户选型企业类型不生效 | loop 主循环与扩散分支在收录前调用 `EnterpriseClassifier.classify(company, extra_text=jd)` 填充 `enterprise_type` |
| G2 | **隐含技能未参与打分**：`match_score` 只算 confirmed 技能，但 missing 计算含隐含 → 打分偏低且口径矛盾 | `match_score` 增加 `implicit` 参数；judge 内联统一匹配逻辑（打分与 missing 用同一组 profile_ids） |
| G3 | **完全匹配岗位被 Gate3 误判**：`missing_skills=[]` 被判"缺少字段" | `validate_job` 仅对 None/缺失报错，空 list 合法 |
| G4 | **JD 深度拆解缺失**：fetch 插件是死代码，JD 仅基于搜索引擎摘要（≤300 字） | 判断改为两阶段：浅判（snippet）→ 对候选岗位抓取正文补全 `jd_text`（≤1500 字）后深判；灰区招聘平台（GREY_HOSTS）不自动抓取；抓取失败降级用摘要 |

### 工程质量修复

| 编号 | 缺陷 | 修复 |
|------|------|------|
| G5 | 进度条硬编码魔法数（65/70/75/80/95），Gate3 质检阶段无进度 | 进度段用 `STEP_WEIGHTS` 推导常量（_SCRUB_BASE 等），补 review 阶段进度 |
| G6 | match 无 Key 异步空转后才失败；cancel 不立即反映；任务结果内存永久保留 | Key 预检快速失败 400；cancel 立即置 cancelling；done/failed 超 30 分钟 TTL 惰性清理 |
| G7 | 搜索链与插件面板脱节：ddgs 面板装 pip 包但实现自解析；Playwright 安装后永不入链 | ddgs 改为内置免安装（self_impl）；Playwright 已安装且启用时加入兜底链 |
| G8 | 死代码 `JUDGE_SYSTEM` prompt（LLM 打分从未接入） | 删除，避免误导维护 |
| G9 | 结果文件同分钟重复运行被覆盖 | 文件名时间戳精确到秒 |
